# v2 设计说明

> v2 是对原平台的整体重写，放在仓库的 `v2/` 子目录，与原项目并存、互不依赖：代码、数据库、前端都是独立的一套。
> 原项目（仓库根目录）不受影响；v2 不迁移原数据库里的数据。

## 1. 这个实验到底在做什么

**目的**：比较不同溶液的导电能力。可比较的量是 **25 °C 下的电导率 κ25**，而且每个数都要能追溯到原始测量。

**测量链**（台架固件 `firmware/esp32_micropython` 已经按这个做了）：

```
双极性方波激励（幅值约 0.2 V，约 10 Hz）
  → 导电池两端电压幅值 U、采样电阻上的电流幅值 I、溶液温度 T      ← 设备（ESP32 + ADS1256 + DS18B20）
  → G = I / U                                                      ← 主机（树莓派）
  → κ(T) = Kcell · G
  → κ25 = κ(T) / (1 + α·(T − 25))
```

- 设备按**自己的节拍**（固件缺省 1 Hz）通过串口推送一行 JSON 帧。帧里是 U/I/T 的原始幅值、设备质量标志（饱和/开路/短路/波形不稳/温度无效/掉线）和设备元数据。
- **Kcell（电池常数）不是配置项，是标定出来的**：用已知 κ25 的标准液（如 KCl 0.01 mol/L = 1413 µS/cm）测出 G，Kcell = κ标准 / G25。没标定之前，所有 κ 都只是「标称 Kcell 下的相对值」。
- 一次**测量**（measurement）= 电极放进某个样品溶液，连续采集直到读数稳定；取稳定段的均值作为该样品的代表 κ25。
- **比较**就是把多次测量的代表 κ25 放在一起看；有浓度时再做浓度–电导率拟合（线性标定 / Kohlrausch 定律）。
- 温度补偿系数 α 可以在一次变温测量里由 κ(T)–T 直线反推，用来检验温补模型。

## 2. 对原项目的批判

以下问题都在原代码里有依据；它们不是某一行的 bug，而是结构性的，逐条修补成本高，这也是 v2 选择重写的原因。

| # | 原项目的做法 | 问题 | v2 的做法 |
|---|---|---|---|
| 1 | 主机按自己的采样率轮询 `driver.read(elapsed)` | 真实设备按自己的节拍推帧。节拍不一致时同一帧会被读成多帧（CSV 回放要手工把 `EC_CSV_SAMPLE_RATE_HZ` 调成设备帧率，正是这个问题） | 设备是**推模式**的异步流：设备产出一帧，主机处理一帧 |
| 2 | 没有串口驱动，真实硬件只能「采成 CSV → 回放」 | 回放丢掉设备的质量标志和元数据，而开路/短路/饱和正是最该进平台的信息 | 串口设备直接解析固件的 JSON 帧；同一个解析器也用于回放采集文件（`.jsonl`） |
| 3 | Kcell 写在驱动配置里，`calibration_records` 只记下驱动声称的值 | 平台里没有真正的标定流程，κ 的绝对值没有依据 | **标定是一等功能**：用一次或多次标准液测量，最小二乘求 Kcell，存标定记录；之后的测量自动使用最新标定，并在测量上记下用的是哪次标定 |
| 4 | κ25 在 `raw_frames` 里存三列（`ec_raw`/`k25`/`kappa_25_us_cm`），另有 `ec` 兼容别名 | 冗余会不一致；`ec` 是废弃的电导率模块路线的遗留 | 帧表**只存原始量**（U/I/T、设备序号与时钟、标志）。G/κ(T)/κ25 由原始量加测量级参数快照（Kcell、α）现算，全平台只有一个计算函数 |
| 5 | U/I/T 不全的帧直接丢弃，不落库 | 温度探头掉线这类故障在历史数据里无痕迹 | 每一帧都落库，缺的量为空并带标志；判稳时算作无效帧 |
| 6 | 「I–V 核心图」对 I–U 散点做回归，还要跨度 ≥0.05 V、R² ≥0.95 两道门槛 | 固件是**固定幅值**激励，U 几乎不变，回归本身是病态的；模拟器的电压扫描只是为了让这张图有东西可画 | 每帧 G = I/U 就是测量结果；U、I 作为诊断量显示 |
| 7 | 判稳的漂移阈值是绝对量（µS/cm/点），还要按采样率换算 | 同样 0.5 µS/cm 的漂移，对 84 µS/cm 是 0.6%，对 12880 µS/cm 可以忽略 | 按时间窗口判稳，漂移与离散都用**相对量**，另查窗口内温度是否稳定；阈值随测量存档 |
| 8 | 拟合模型池：线性/二次/指数/对数/幂/一阶饱和/Arrhenius/Kohlrausch × 三个坐标轴，另有 AICc/LOOCV | 对这个实验有物理意义的只有三件事：κ25–浓度（线性、Kohlrausch）、κ(T)–T 求 α、时间漂移（已归判稳）。其余模型只会让人拟合出没有意义的曲线 | 只保留这三个分析，都是线性最小二乘，给参数、标准误、95% 置信区间、R²、残差和有效区间 |
| 9 | 「续跑」：停止后同样品再开始就接着写同一条实验 | 为此要做时间轴偏移、续跑去重窗口、历史帧回灌、重连归属对齐，是前后端最复杂、出 bug 最多的部分 | 不续跑。每次开始都是一条新测量；同一样品测多次，在比较时按样品看 |
| 10 | 落库失败进入进程级降级闩锁，拒收后续帧，要重启后端才恢复 | 一次偶发写失败就永久丢数据 | 写失败的帧留在内存里，下次重试（有上限）；数据库恢复后自动续上 |
| 11 | 前端另有一个「浏览器模拟模式」 | 与后端模拟器是两套实现，行为会分叉 | 只有后端一个模拟器，前端永远连后端 |
| 12 | 前端先走 REST 拉历史、再从 WS 收帧，靠 generation 计数处理竞态 | 两个通道的消息顺序无保证，重连逻辑复杂且难测 | WS 连上时服务端先发一个**快照**（状态 + 当前曲线），之后按序发增量。前端是一个对有序消息的纯函数 reducer |
| 13 | 采集任务一直在跑，但「看读数」和「记录」混在一个实验状态机里 | 实验者需要在开始记录前看读数是否稳定、温度是否到位 | 明确分成**监视**（设备一直出读数，只显示不落库）和**记录**（测量进行中才落库） |
| 14 | 数据接入测试用锂电池循环、循环伏安等公开数据集 | 这些都不是电导池数据，只验证了「CSV 能读进来」 | 测试夹具使用固件格式的帧 |
| 15 | CORS 白名单放行局域网，控制接口可被任意网页跨站触发 | 已知问题 #9 | 前端与 API 同源（开发时也经 Vite 代理），不开 CORS；另外校验 `Origin`，拒绝跨站的写请求和 WS |

原项目仍然有很多值得保留的判断，v2 都继承了：原始量不可变、帧表 append-only（触发器禁止改删）、单一后台采集任务与连接数解耦、每客户端有界队列广播、数据库迁移一个版本一个事务、无硬件也能完整演示。

## 3. 架构

```
设备（三选一，推模式异步流）          主机：FastAPI 单进程                              浏览器（同源）
┌────────────────────────┐   Reading   ┌──────────────────────────────────────┐  WS 快照+增量  ┌──────────────┐
│ SerialDevice  串口 JSON 帧│ ─────────→ │ Lab：监视缓冲 / 当前测量 / 批量落库 / 实时判稳 │ ────────────→ │ 测量 / 记录 /  │
│ ReplayDevice  回放 .jsonl │            │   chemistry（唯一计算链）  qc（判稳）       │ ←──── REST ── │ 标定 三个页面   │
│ SimulatedCell 物理模拟    │            │   store（SQLite）  fitting（线性最小二乘）  │               └──────────────┘
└────────────────────────┘            └──────────────────────────────────────┘
```

后端模块（`v2/backend/ec/`），每个模块只做一件事：

| 模块 | 职责 |
|---|---|
| `settings.py` | 读取并校验全部环境变量（唯一入口，报错指明变量名） |
| `chemistry.py` | 计算链 U/I/T → G → κ(T) → κ25；标准液表；KCl 浓度模型（给模拟器用） |
| `frames.py` | 设备帧的数据结构、固件 JSON 帧解析、序号跳号/设备重启检测 |
| `devices.py` | 三种设备：模拟、串口、回放。统一接口：`stream()` 异步产出读数与设备状态 |
| `qc.py` | 判稳：时间窗口、相对漂移、变异系数、温度稳定、无效帧占比 |
| `fitting.py` | 线性最小二乘（含过原点），浓度拟合、温度系数拟合、Kcell 标定 |
| `store.py` | SQLite：建表与迁移、测量/帧/标定的读写 |
| `hub.py` | WebSocket 广播：每客户端一个有界队列，慢客户端丢旧帧 |
| `lab.py` | 核心编排：消费设备流、维护监视与测量状态、批量落库、开始/停止测量、标定 |
| `app.py` | HTTP/WS 接口与静态文件托管 |

前端（`v2/frontend/`）：React + TypeScript + Vite，图表用 uPlot（约 50 KB，比 ECharts 小一个数量级，树莓派上重绘更轻）。三个页面：**测量**（监视、开始/停止、实时判稳、结果）、**记录**（历史列表、详情、导出、比较与浓度拟合）、**标定**（Kcell 标定与标定历史）。

## 4. 数据模型

- `measurements`：一次测量。样品信息（名称、浓度、备注），起止时间与状态（running/completed/aborted），**参数快照**（Kcell、所用标定、α、设备元数据、激励设置），停止时写入的判稳结果（结论、代表 κ25、标准差、点数、窗口内温度、所用阈值）。
- `frames`：原始帧，append-only。测量内序号、相对时间、UTC 时间、设备序号与设备时钟、U/I/T（可为空）、质量标志。
- `calibrations` + `calibration_points`：一次标定及其各个标准液点（哪次测量、标准液名称与标称 κ25、测得的 G25、偏差）。

判稳结果写入后测量不再修改；帧和标定只插入不修改。

## 5. 质量标志

| 标志 | 来源 | 判稳时 |
|---|---|---|
| `SATURATED` `OPEN_CIRCUIT` `SHORT_CIRCUIT` `DROPOUT` | 设备 | 硬异常，窗口内出现即 FAIL |
| `WAVEFORM_UNSTABLE` | 设备 | 提示，窗口内出现降为 WARN |
| `TEMP_INVALID` | 设备 | 温度为空 → 无法温补 → 无效帧 |
| `POLARITY` | 主机 | U ≤ 0 或 I < 0（接线反了），G 无定义 → 硬异常 |
| `SEQ_GAP` `DEVICE_RESTART` | 主机 | 设备序号跳号（串口丢行）/ 回退（设备重启），仅记录 |

## 6. 取舍与不做的事

- **不续跑、不删除**：测量一旦开始就是一条独立记录；错误的测量保留，在比较时不选它即可。
- **不做 PDF 报表、不做鉴权**：导出 CSV 与 JSON；鉴权仍按原项目登记为上线前必做项（v2 已做同源 + Origin 校验）。
- **不做 pH/ORP、三电极**：与电导率链路无关，按原路线图单独立项。
- **判稳阈值是初设值**：未经台架标定，随每次测量存档，以便日后复核。
- **不声明精度**：沿用原路线图的总闸门，台架证据齐之前不声明精度、量程和温补误差。
