# v2 接口说明

> 依据代码：`v2/backend/ec/app.py`（HTTP/WS）、`lab.py`（推送消息）、`frames.py`（设备帧）、`store.py`（数据库）、`settings.py`（环境变量）。
> 前端类型定义与这里一一对应：`v2/frontend/src/lib/types.ts`。

## 1. 约定

- 前端与接口**同源**：生产由后端托管 `frontend/dist`；开发时 Vite（:5174）把 `/api`、`/ws` 代理到后端。后端不开 CORS。
- 浏览器发来的写请求（POST）和 WS 连接如果带着别的站点的 `Origin`，返回 403 / 关闭连接（1008）。不带 `Origin` 的请求（curl、脚本）不受影响。
- 单位：U [V]，I [A]，G [S]，Kcell [cm⁻¹]，κ [µS/cm]，T [°C]，浓度 [mmol/L]，时间 [s]。
- 时间戳是 UTC ISO 8601，毫秒精度，以 `Z` 结尾。
- 错误体：`{"detail": "中文原因"}`。状态码：404 不存在、409 与当前状态冲突、422 请求不满足条件、503 设备未连接或数据库暂时写不进去。
  请求体校验失败也是 422，`detail` 为 `[{"loc": [...], "msg": "...", "type": "..."}]`（不回显输入值）。

## 2. 数据点（Point）

实时推送与历史查询用同一种数据点，G/κ(T)/κ25 都由原始量加测量参数现算：

| 字段 | 说明 |
|---|---|
| `seq` | 测量内序号，从 1 起；监视读数为 `null` |
| `t_s` | 测量开始后的秒数（监视时是后端启动后的秒数）。相邻帧的间隔优先取设备时钟（`monotonic_ms`）之差，设备时钟缺失或回退（设备重启）时用主机时钟：串口收帧延迟不进时间轴，加速回放时仍是设备时间 |
| `voltage_v` / `current_a` / `temperature_c` | 原始 U / I / T，缺失为 `null` |
| `conductance_s` / `kappa_t_us_cm` / `kappa25_us_cm` | G / κ(T) / κ25，算不出为 `null` |
| `flags` | 质量标志数组（见设计说明 §5）；`POLARITY` 由主机按 U、I 的符号判定 |

## 3. REST

| 方法与路径 | 说明 |
|---|---|
| `GET /api/state` | 当前状态（与 WS 快照里的 `state` 相同，见 §4） |
| `GET /api/standards` | 标准液预设：`[{name, kappa25_us_cm}]` |
| `POST /api/measurements` | 开始测量。请求体 `{sample_name, concentration_mmol_l?, note?}`；201 返回测量。已有测量 409，设备未连接 503 |
| `POST /api/measurements/current/stop` | 停止当前测量：落库、判稳、写结果，返回测量。没有进行中的测量 409；数据库写不进去 503（测量继续记录） |
| `GET /api/measurements?limit=&offset=` | 测量列表（新的在前），含 `frame_count`、`duration_s`、`qc` |
| `GET /api/measurements/{id}` | 单个测量 |
| `GET /api/measurements/{id}/points?max_points=4000` | `{measurement_id, total, step, points}`；超过 `max_points` 时等间隔抽样（保留最后一点） |
| `GET /api/measurements/{id}/frames.csv` | 全部帧：`seq,t_s,timestamp_utc,device_seq,device_ms,voltage_v,current_a,temperature_c,conductance_s,kappa_t_us_cm,kappa25_us_cm,flags` |
| `GET /api/measurements/{id}/temperature-fit` | 由 κ(T)–T 估计 α 与 κ25（温度跨度 ≥ 2 °C、有效点 ≥ 10） |
| `POST /api/analysis/concentration` | 请求体 `{measurement_ids: [≥2 个]}`。每个测量须正常结束、有代表值、填了浓度。返回线性标定与 Kohlrausch 拟合，所选测量用了不同 Kcell 时 `warnings` 非空 |
| `GET /api/calibrations` | 标定历史（新的在前），含各标准液点 |
| `POST /api/calibrations` | 新建标定并立即启用，见 §3.2；测量进行中 409 |
| `POST /api/simulator` | 仅模拟器：`{fault?, kappa25_us_cm?}`。故障：`none` `air` `no_temp` `drift` `noisy` `dropout` `reversed` |

### 3.1 测量（Measurement）

`id, sample_name, concentration_mmol_l, note, status (running|completed|aborted), started_at, ended_at`，
参数快照 `cell_constant_per_cm, calibration_id, alpha_per_c, device_kind, device_id, firmware_version, range_id, excitation_frequency_hz, excitation_amplitude_v`，
以及 `qc`（停止时写入；中断的测量为 `null`）：

| 字段 | 说明 |
|---|---|
| `verdict` | `PASS` / `WARN` / `FAIL` |
| `reasons` | 原因代码数组：`hard_flags` `too_many_invalid` `insufficient_points` `high_variation` `drift`（任一出现即 FAIL）；`some_invalid` `variation` `slight_drift` `temperature_unstable` `waveform_unstable` `window_incomplete`（WARN） |
| `hard_flags` | 窗口内出现的硬异常标志 |
| `n_points` / `n_valid` / `window_s` | 窗口内帧数 / 有效帧数 / 实际跨度 |
| `kappa25_mean` / `kappa25_sd` / `cv` / `drift` | 有效 κ25 的均值、标准差、变异系数、窗口内相对漂移 |
| `temperature_mean` / `temperature_span` | 窗口内温度均值与跨度 |
| `representative_kappa25` | 代表值：非 FAIL 时等于均值，FAIL 时为 `null` |
| `config` | 判稳所用阈值（随测量存档） |

### 3.2 标定

请求体：

```json
{
  "points": [
    {"measurement_id": 12, "standard_name": "KCl 0.01 mol/L", "standard_kappa25_us_cm": 1413},
    {"measurement_id": 13, "standard_name": "KCl 0.001 mol/L", "standard_kappa25_us_cm": 147}
  ],
  "operator": "张三", "lot": "B-2026-09", "cell_id": "cell-A", "note": null
}
```

每个点取该次测量的代表 κ25，按测量当时的 Kcell 反推 G25 = κ25 / Kcell；再按 κ标准 = Kcell·G25 过原点最小二乘求新 Kcell。
每个测量须正常结束且有代表值（PASS 或 WARN）。返回标定记录和 `fit`：`points[].deviation_pct` 是用新 Kcell 算回去与标称值的偏差，任一点超过 5% 拒绝（422，说明标准液与测量对不上）；`rsd_pct` 是各点单独求出的 Kcell 的相对标准差（同一标准液重复装夹时的重复性）。过原点拟合的 `r2` 只在标准液跨越量程时有参考意义，同一标准液重复测量时可能为负，不作判据。
新标定只影响之后开始的测量。

## 4. WebSocket `/ws`

服务端推送 JSON 文本，客户端不需要发消息。

| `type` | 内容 | 何时 |
|---|---|---|
| `snapshot` | `state`、`points`（记录中为当前测量的点，否则为最近的监视读数）、`qc`（记录中的实时判稳） | 连接后第一条；客户端太慢、队列溢出时也会重发 |
| `state` | `state` | 设备连接/日志、测量开始/结束、标定变化、落库出错/恢复 |
| `reading` | `measurement_id`（监视为 `null`）、`point`、记录中另有 `qc` | 设备每出一帧 |
| `heartbeat` | — | 5 s 内没有其他消息时 |

`state` 的字段：`device {kind, connected, message, info}`、`measurement`（进行中的测量或 `null`）、`last_finished`（本次运行最后结束的测量）、`calibration`（当前标定或 `null`）、`cell_constant_per_cm` 与 `alpha_per_c`（此刻开始测量会用的值）、`qc_config`、`storage_error`。

顺序保证：先改状态再发布，所以「测量开始」的 `state` 一定在该测量的第一条 `reading` 之前。
客户端的规则很简单：收到 `snapshot` 整体替换；`state` 里的测量变了就清空曲线；`reading` 只收 `measurement_id` 与当前测量一致的。

## 5. 设备帧（串口 / 回放文件）

与 ESP32 固件（`firmware/esp32_micropython/main.py`）一致：每行一个 JSON 对象，以 `# ` 开头的行是设备日志。

| 字段 | 说明 |
|---|---|
| `seq_no` | 设备帧序号（必需）；跳号记 `SEQ_GAP`，回退记 `DEVICE_RESTART`（停止测量时数据库写失败、测量恢复记录后的第一帧也记 `SEQ_GAP`） |
| `monotonic_ms` | 设备单调时钟；回放按它的间隔控制节奏 |
| `voltage_raw_v` / `current_raw_a` / `temperature_raw_c` | 原始 U / I / T，`null` 表示缺失（三者至少出现一个字段） |
| `quality_flags` | `"A|B"` 或 `null` |
| `device_id` / `firmware_version` / `range_id` / `excitation_frequency_hz` / `excitation_amplitude_v` | 设备元数据，开始测量时存入参数快照 |

类型不对的值（字符串数字、布尔、NaN/Inf）按缺失处理，不会让整帧出错。串口按换行分帧：pyserial 读超时返回的半行会先攒着，攒到换行再解析。
每次打开串口，主机先发 `\x03\x02\x04`（Ctrl-C 停掉在跑的程序、Ctrl-B 退出 raw REPL、Ctrl-D 软重启），让 MicroPython 重新运行 `main.py`：Thonny 连接时会中断 `main.py`，断开后板子停在 REPL。所以每次连接的设备序号都从 1 开始，前面是器件自检日志。
串口设备的「已连接」指正在收到设备帧：串口打开后、第一帧之前报未连接（设备日志照常上报为状态消息），出帧后连续 5 次读超时（约 5 s）没有任何数据也改报未连接；`device.connected` 为假时不能开始测量。回放文件就是 `capture_serial.py` 生成的 `.jsonl`；
`v2/samples/simulated_kcl_10mM.jsonl` 是一个示例。

## 6. 数据库

SQLite，`PRAGMA user_version` 记版本（当前 1），迁移一个版本一个事务。

| 表 | 内容 | 约束 |
|---|---|---|
| `measurements` | 样品、状态、参数快照、`qc`（JSON） | 不能删；样品与参数列不能改；只有 running 的测量能被结束一次 |
| `frames` | `(measurement_id, seq)` 主键；原始 U/I/T、设备序号与时钟、标志 | 只能插入 |
| `calibrations` / `calibration_points` | 标定与各标准液点 | 只能插入 |

## 7. 环境变量

| 变量 | 缺省 | 说明 |
|---|---|---|
| `EC_DEVICE` | `sim` | `sim` 模拟 / `serial` 串口 / `replay` 回放 |
| `EC_SERIAL_PORT` / `EC_SERIAL_BAUD` | `/dev/ttyUSB0` / `115200` | 串口设备 |
| `EC_REPLAY_PATH` / `EC_REPLAY_SPEED` / `EC_REPLAY_LOOP` | — / `1` / `0` | 回放文件、倍速、是否循环 |
| `EC_SIM_RATE_HZ` / `EC_SIM_SEED` / `EC_SIM_SETTLE_S` | `2` / 随机 / `1` | 模拟器帧率、随机种子、换溶液后的趋稳时间常数 |
| `EC_CELL_CONSTANT` | `1.0` | 没有标定时使用的标称 Kcell |
| `EC_ALPHA` | `0.02` | 线性温补系数 α（/°C） |
| `EC_QC_WINDOW_S` | `30` | 判稳窗口（s） |
| `EC_DB_PATH` | `v2/data/ec.db` | 数据库文件 |
| `EC_STATIC_DIR` | `v2/frontend/dist` | 前端产物目录（有 `index.html` 才托管） |
| `EC_HOST` / `EC_PORT` | `127.0.0.1` / `8000` | 监听地址；局域网访问用 `0.0.0.0` |

非法值启动即报错并指明变量名（退出码 2）。
