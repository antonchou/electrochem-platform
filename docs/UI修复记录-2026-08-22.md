# UI 修复记录 · 拟合面板与图表（2026-08-22）

## 背景

用户反馈：拟合公式时图表"图标分辨率低"、图表线条颜色与图例颜色不一致。以此为入口对前端做了一次完整 UI 审查，共确认 2 个直接问题 + 8 个隐含问题，本文档记录全部修复内容。

> 版本状态：第 1–9 项已随提交 `18d6414 fix(frontend): improve chart UI and fit state handling` 入库（含新增 e2e 用例「拟合中切换模型：旧响应不得覆盖当前选择」）；第 10 项为当日追加修复。

## 修复清单

### 1. 图例 / tooltip 颜色与线条颜色不一致（Bug）

- **根因**：`StaticChart.tsx` 只设置了 `lineStyle.color`。ECharts 的图例色块与 tooltip 圆点取色自**全局调色板**（默认 `#5470c6/#91cc75/...`），与 `lineStyle` 无关，导致图例颜色与线条完全对不上。`RealTimeChart` 因同时设置了 `itemStyle.color` 而无此问题。
- **改动**：`frontend/src/components/StaticChart.tsx`
  - `setOption` 顶层新增 `color: ['#2f6fed', ...overlays 颜色]` 全局调色板；
  - 每条 series 补充 `itemStyle.color`，与 `lineStyle.color` 保持一致。

### 2. 图表模糊（"分辨率低"）与图例图标过细

- **根因 A**：两个图表组件都只监听 `window.resize`。容器宽度变化但不触发窗口 resize 时（历史弹窗出现内部滚动条、ErrorBanner 挤出布局等），canvas 保持初始像素尺寸被 CSS 拉伸，显示模糊。
- **根因 B**：图例图标被设为 `roundRect 14×6`，视觉上是难以辨认的细条。
- **改动**：`frontend/src/components/StaticChart.tsx`、`frontend/src/components/RealTimeChart.tsx`
  - 新增 `ResizeObserver` 监听容器尺寸并调用 `chart.resize()`（含 `typeof ResizeObserver !== 'undefined'` 兜底）；
  - 图例图标放大为 `18×8`；
  - `StaticChart` 的 `grid` 改为 `containLabel: true`，避免长 Y 轴刻度被裁剪。

### 3. 图例文本过长单行溢出

- **根因**：图例名为完整公式 + R²（如"一阶指数饱和 y = a − b·e^(−k·x) (R²=0.9983)"），4 条拟合 + 实测共 5 项，plain 单行图例在窄屏/弹窗内溢出被裁。
- **改动**：`StaticChart.tsx` 图例改为 `type: 'scroll'`。

### 4. HistoryPanel 违反 React Hooks 规则（潜伏崩溃）

- **根因**：`if (!api) return` 提前返回之后仍调用 3 个 `useMemo`。一旦 `api` 在运行中由 null 变为非 null，React 因 Hook 数量不一致直接崩溃（"Rendered more hooks than during the previous render"）。
- **改动**：`frontend/src/components/HistoryPanel.tsx` —— 将 `chartData` / `displayData` / `historyPoints` 三个 `useMemo` 上移到 early return 之前，并加注释说明约束。

### 5. 浏览器模拟模式下「开始拟合」永久禁用且无任何提示

- **根因**：`canFit` 要求 `api !== null`，而 browser 模式 `api` 恒为 null，按钮灰置但界面无解释。
- **改动**：`frontend/src/components/FitPanel.tsx` —— `!api` 时显示提示条（`data-testid="{prefix}-no-api-note"`）："浏览器模拟模式下无后端拟合接口……请切换 server 模式"。

### 6. 切换模型勾选后旧结果不过期

- **根因**：`toggleModel` 只改勾选状态，旧结果表与曲线继续显示，与当前所选模型不再对应（切换 X 轴有清空，切换模型没有）。
- **改动**：`FitPanel.tsx` —— `toggleModel` 中同步清空 `fitResults` 与 `fitError`；提交 18d6414 同时补充了竞态防护与对应 e2e 用例（拟合中切换模型，旧响应不得覆盖当前选择）。

### 7. 全部模型拟合失败时界面静默

- **根因**：后端返回 `models: []` 时既不显示错误也不显示结果，用户点击后毫无反馈。
- **改动**：`FitPanel.tsx` —— `fitResults.length === 0` 时显示提示条（`data-testid="{prefix}-empty"`）。

### 8. 结果表格与曲线无颜色对应

- **根因**：表格列出全部模型，曲线仅绘制 R² 前 4 条，行内无色块指示，无法把曲线与公式对应。
- **改动**：
  - `FitPanel.tsx` —— 公式列前加色块 `<span class="swatch">`，颜色与 overlay 的 `CURVE_COLORS[i]` 一一对应（仅前 4 行）；结果超过 4 条时显示"曲线图仅绘制 R² 最高的前 4 条"；
  - `FitPanel.module.css` —— 新增 `.swatch` / `.curveNote` 样式。

### 9. 死代码清理

- **根因**：`ResultPanel.module.css` 中约 154 行是 `FitPanel.module.css` 的整份复制（`.reserved`/`.fitHead`/`.axisChip` 等 15 个类），`ResultPanel` 组件从未使用。
- **改动**：删除该副本，仅留注释说明拟合区样式由 `FitPanel.module.css` 提供。

### 10. 图例与 Y 轴名称重叠（当日追加）

- **根因**：`StaticChart` 的 `grid.top` 仅 34px，小于「图例条高度 + Y 轴名称高度」。Y 轴名称 `EC (μS/cm)` 默认绘制在轴线顶端，正好落入顶部图例条区域，与图例首项（"实测"）重叠。拟合面板图表高度仅 220px，问题更明显。
- **改动**：
  - `StaticChart.tsx` —— `grid.top` 34 → 52，并加注释说明该约束；
  - `FitPanel.tsx` —— 拟合图高度 220 → 240，补偿 grid 顶部加大后变挤的绘图区。
- **验证**：修复前后各截图一张人工比对，重叠消除；图例条、Y 轴名称、绘图区三层自上而下互不遮挡。

## 兼容性说明

- 所有 `data-testid` 保持不变，新增提示使用新的 testid（`-no-api-note`、`-empty`），不影响既有 e2e 断言。
- 结果表"公式"列在文本前新增色块 `<span aria-hidden>`，不影响 `toContainText('线性')` 等文本断言。

## 备注（环境）

- 本机跑 e2e 时 Playwright 的 `webServer` 使用 PATH 上的 `python`（managed 3.13 无 uvicorn 会启动失败）；需先用系统 Python 3.12（已装 uvicorn）手动启动后端与前端 dev server，测试会以 `reuseExistingServer` 复用。
- 沙箱的 safe-delete 会拦截 Vite 清空 `dist/` 与 `node_modules/.vite` 缓存：构建验证可用 `--outDir dist-verify` 绕过；dev server 启动失败时手动删除 `node_modules/.vite` 后重启。
