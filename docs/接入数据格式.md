# 数据接入格式规格（Raw → Derived 计算链）

> 状态：**正式规格**（硬件接入契约，N2 电气台架 / 真实驱动的对接依据）
> 生效日期：2026-08-23
> 关联：`docs/电导率I-V测量链路与开发路线.md`（硬件链路）、`docs/电导率I-V开发路线_评审与验收标准.md`（N4 计算闭环）、`backend/app/measurement.py`（计算链唯一实现）、`docs/数据接口文档.md`（接口契约全集）
> 版本：v1.1（2026-09-30：§4 驱动接入契约补充 `DriverConfig`；帧带 `experiment_id`）

## 1. 数据模型总览

一帧数据分两层：

| 层 | 字段 | 谁产生 | 是否可变 |
|---|---|---|---|
| **Raw（原始）** | 时间 `t`、电压 `U`、电流 `I`、温度 `T` | 硬件驱动（或 Mock 仿真） | **不可变**，落库后只追加 |
| **Derived（计算）** | 电导 `G`、电导率 `κ(T)`、温补电导率 `κ25` | 后端计算链 `measurement.compute_chain` | 可重算，可随参数版本追溯 |

**核心原则（对应原路线图 §2 / REQ-M-001）：**
- `U/I/T/t` 是不可变原始量，直接来自硬件，**不覆盖、不修改**；
- `G / κ(T) / κ25` 是可重算结果，**由后端统一计算**，驱动不参与计算；
- 校准、滤波、温补、人工修订**不得覆盖原始数据**。

**计算链唯一实现**：`backend/app/measurement.py::compute_chain()`。
真实驱动、Mock、以及任何接入方都不得各自实现一套计算——计算逻辑必须唯一，才能保证可重算、可审计、可追溯。

## 2. Raw 原始数据字段（4 个）

| 字段名 | 物理量 | 单位 | 类型/精度 | 说明 |
|---|---|---|---|---|
| `t`（实时协议 `timestamp`，落库 `t_seconds`） | 时间 | s | float，≥0 | 实验开始后的相对时间，测量轴；必须单调不减 |
| `voltage_raw_v` | 激励电压 U | V | float | 受控激励实测电压；**必须 > 0**（0/负无法定义电导） |
| `current_raw_a` | 回路电流 I | A | float | 电压通道实测电流（采样电阻/TIA 换算后） |
| `temperature_raw_c` | 温度 T | °C | float | 导电池附近溶液温度，非机箱/板卡温度 |

> 溯源字段（非物理量，随帧）：`experiment_id`（所属实验，DB id）、`seq_no`、`timestamp_utc`、`monotonic_ms`、`sensor_path_id`、`device_id`、`firmware_version`、`range_id`、`schema_version`、`calibration_id`、`excitation_frequency_hz`、`excitation_amplitude_v`、`compensation_model`。其中设备/激励/校准元数据取自驱动 config（§4）。
> 质量标志：`quality_flags`（`|` 分隔，见 §5）。κ25 落库/导出规范名为 `kappa_25_us_cm`。

## 3. Derived 计算数据字段（3 个）

由原始数据经 `measurement.compute_chain()` 计算得出：

| 字段名 | 物理量 | 单位 | 公式 |
|---|---|---|---|
| `conductance_s` | 电导 G | S | `G = I / U` |
| `kappa_t_us_cm` | 电导率 κ(T) | μS/cm | `κ(T) = Kcell × G × 1e6` |
| `kappa_25_us_cm` | 温补电导率 κ25 | μS/cm | `κ25 = κ(T) / [1 + α × (T − 25)]` |

单位换算：`1 S/cm = 1e6 μS/cm`；`Kcell` 单位 `cm⁻¹`，由标准液标定（N3，关联 `calibration_id`）。

### 3.1 计算链公式（`backend/app/measurement.py`）

```
G(T)     = I / U                      # 电导，S
κ(T)     = Kcell · G(T)               # 电导率，μS/cm（乘 1e6 换算）
κ25      = κ(T) / [1 + α · (T − 25)]  # 温度补偿到 25°C
```

**输入校验（compute_chain 强制）：**
- `voltage_v > 0`（0/负电压 → ValueError）
- `cell_constant_per_cm > 0`
- 温补分母 `1 + α·(T−25) ≠ 0`（α/T 组合致分母归零 → ValueError）
- 输入与结果都必须是有限数（NaN/inf → ValueError，帧标 `COMPUTE_INVALID`）

**计算法约定（对应路线图 §2）：** `G = I/U` 的实现方式（同频幅值 / RMS / 复导纳）须在硬件设计冻结时**唯一确定**，不得混用。

## 4. 驱动接入契约（真实硬件 / Mock 统一边界）

接入方（驱动）只做两件事，全部计算由后端完成：

1. 每次 `read()` 产出 **4 个 Raw 量 + quality_flags**（`DriverReading`）；
2. 用 **config**（继承 `DriverConfig`）声明采样率、计算参数和设备/激励/校准元数据。

```python
# backend/app/drivers/base.py
@dataclass(frozen=True, slots=True)
class DriverReading:
    ec: float | None                # 兼容别名（= κ25），可空
    temperature: float | None       # 兼容别名（= temperature_raw_c），可空
    ph: float | None = None         # 预留给后续 pH 通道
    voltage_v: float | None = None  # Raw: U [V]
    current_a: float | None = None  # Raw: I [A]
    quality_flags: tuple[str, ...] = ()

    @property
    def complete_for_iv(self) -> bool:
        # U/I/T 都是有限数才算完整；NaN/inf（如探头读失败）等同缺失，整帧跳过
        return _finite(self.voltage_v) and _finite(self.current_a) and _finite(self.temperature)


@dataclass(frozen=True, slots=True, kw_only=True)
class DriverConfig:
    sample_rate_hz: float = 10.0             # 采样率 Hz，须 > 0
    cell_constant_per_cm: float = 1.0        # Kcell [cm⁻¹]，须 > 0
    alpha_per_c: float = 0.02                # 线性温补系数 α [/°C]
    excitation_frequency_hz: float = 1000.0  # 激励频率；0 = 直流
    excitation_amplitude_v: float = 1.0      # 激励幅值 [V]
    compensation_model: str = "linear_alpha"
    device_id: str = "UNKNOWN"
    firmware_version: str = "0.1.0"
    range_id: str = "UNKNOWN"
    calibration_id: str | None = None
    calibration_standard: str | None = None
    calibration_lot: str | None = None
    calibration_claimed: bool | None = None  # None = 未声明，由 calibration_id 推导


class DeviceDriver(ABC):
    config: DriverConfig
    connected: bool                                        # 只读属性
    async def connect(self) -> None: ...
    async def close(self) -> None: ...
    async def read(self, elapsed_seconds: float) -> DriverReading: ...
```

**config 字段去向：**

| 字段 | 用途 |
|---|---|
| `sample_rate_hz` | 采集循环节拍（按截止时刻调度） |
| `cell_constant_per_cm` / `alpha_per_c` | `compute_chain` 的 Kcell 与 α |
| `device_id` / `firmware_version` / `range_id` / `excitation_frequency_hz` / `excitation_amplitude_v` / `compensation_model` / `calibration_id` | 每帧随帧下发并落库（§2 溯源字段） |
| 以上全部 + `calibration_standard` / `calibration_lot` | 新实验开始时写一条 `calibration_records`（`coeff_json` 为系数快照） |
| `calibration_claimed` | `true` = 已校准；`false` = 未校准，帧追加 `UNCALIBRATED`（有校准编号也不覆盖）；`None` = 未声明，存在非 `UNCALIBRATED` 的 `calibration_id`（驱动声明或 `EC_CALIBRATION_ID`）即视为已校准 |

**新驱动接入步骤：**

1. 写 config 类继承 `DriverConfig`（同样加 `kw_only=True`），只覆盖与缺省不同的字段，驱动自有参数写在同一个类里。需要额外校验时，`__post_init__` 里先调 `DriverConfig.__post_init__(self)`（slots dataclass 不能用无参 `super()`）。
2. 写驱动类继承 `DeviceDriver`，实现 `connect / close / read`；`read` 只填 Raw 量与 `quality_flags`，不做任何计算。
3. 在 `acquisition.build_driver()` 里按 `EC_DRIVER` 取值注册，业务层与前端不用改。
4. 从 JSON 加载配置时，字段名即 config 字段名，未知字段直接报错（现有驱动的 `from_mapping` 可照抄）。

示意（字段取值以实际硬件为准）：

```python
@dataclass(frozen=True, slots=True, kw_only=True)
class BenchConfig(DriverConfig):
    port: str = "/dev/ttyUSB0"               # 驱动自有参数
    sample_rate_hz: float = 1.0
    device_id: str = "ESP32-BENCH-01"
    range_id: str = "R1K"
    calibration_claimed: bool | None = False  # 标准液标定（N3）前如实声明未校准
```

内置驱动的缺省值：Mock `MOCK-IV-01` / `WIDE` / `MOCK-KCELL-1.0`（已校准）；Simulator `SIM-IV-01` / `SIM` / `SIM-KCELL-1.0`（未校准）；CSV 回放 `CSV-PLAYBACK-01` / `CSV` / `UNCALIBRATED`（未校准，激励频率 0）。没有 config 的驱动（仅测试替身）按 `DriverConfig` 缺省值组帧。

**职责划分：**
- **驱动**：采样 `U/I/T` → 填 `voltage_v / current_a / temperature` + `quality_flags`；用 config 声明参数与元数据。不做 `G/κ(T)/κ25` 计算。
- **后端采集循环**（`acquisition.run()` → `_build_frame`）：当 `complete_for_iv` 为真，按 config 的 Kcell/α 调 `measurement.compute_chain()` 算 `G/κ(T)/κ25`，组装完整帧 → 落库 → 广播。读数抛异常时指数退避重试（上限 5 s），任务不退出。
- **Mock**（`drivers/mock.py`）：由目标 κ25 **反推** `U/I`（受控激励电压取 `excitation_amplitude_v`，含 ±0.1% 电压、±0.5% 电流噪声），模拟真实前端；真实硬件接入后按同一 `DriverReading` + `DriverConfig` 边界替换，**前端与协议零改动**。

## 5. 质量标志（quality_flags）

`|` 分隔的字符串，逐点随帧。约定取值：

| 标志 | 含义 |
|---|---|
| `SIMULATED` | 模拟数据源（非真实硬件） |
| `DROPOUT` | 丢点/读值缺失 |
| `OUT_OF_RANGE` | 超出量程（κ<0 或 pH 越界等） |
| `SATURATED` | 饱和（过量程） |
| `OPEN_CIRCUIT` | 开路 |
| `SHORT_CIRCUIT` | 短路 |
| `UNDER_RANGE` | 欠量程 |
| `TEMP_INVALID` | 温度无效 |
| `UNCALIBRATED` / `CALIBRATION_EXPIRED` | 校准缺失/过期 |
| `WAVEFORM_UNSTABLE` | 波形不稳 |

`SATURATED / OPEN_CIRCUIT / SHORT_CIRCUIT / UNDER_RANGE / OUT_OF_RANGE / CURRENT_ZERO` 为**硬异常**，判稳时直接 FAIL（REQ-D-003）。
后端组帧层还会追加 `UNCALIBRATED`、`COMPUTE_INVALID`、`PERSIST_DROPPED`；各驱动实际产生的完整标志字典见 `docs/数据接口文档.md` §6。

## 6. 兼容层（旧前端 / 旧数据不破）

- 实时帧保留 V1 别名：`ec`（= κ25）、`temperature`（= temperature_raw_c）、`status`；旧前端只读这 3 个字段照常工作。
- 前端 `protocol.ts` 中新增字段**全部可选**，缺字段照常解析（`parseServerMessage` 向后兼容）。
- 数据库旧库升级：v1 历史帧的 `voltage_raw_v` 等新列为 NULL，旧行保留；查询/导出时旧列名（`ec_raw_us_cm` / `temperature_raw_c`）不变。
- **过渡门槛**：新增字段 + 迁移 + E2E 全绿 → 才允许废止旧别名（当前未废止）。

## 7. 数据流全链路

```text
硬件(或 Mock) U/I/T/t + quality
   → DriverReading（驱动边界，Raw only）
   → compute_chain: G = I/U, κ(T) = Kcell·G, κ25 = κ(T)/(1+α(T-25))
   → Frame（Raw + Derived + 溯源 + 兼容别名）
   → 落库 raw_frames（append-only）
   → WebSocket 广播 → 前端分层显示（U / I / G / κ(T) / κ25）
```

验收标准见 `docs/电导率I-V开发路线_评审与验收标准.md` N4（数值误差 <0.1%、全链路 30min 无断流、原始数据只写不覆盖）。
