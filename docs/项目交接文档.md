## 5. 核心架构与数据流

```
                    ┌─────────────── 实时链路（10Hz）───────────────┐
 [Mock/FastAPI] ws_frame ─► WebSocket ─► websocketClient ─► 曲线/数值（200ms 节流刷新）
        │
        └► persistence（Queue 攒批）─► SQLite raw_frames（append-only）
                                        │
                                        ├─► REST 历史列表/详情/帧
                                        ├─► 导出 CSV / JSON
                                        └─► 拟合：POST /api/analysis/fit ─► FitPanel（结果区+历史详情复用）
```

关键设计：
- **append-only（REQ-D-001）**：`raw_frames` 建触发器禁止 `UPDATE`/`DELETE`，原始数据不可篡改，导出即取证。
- **先落库再推送**：`ws_stream` 先 `enqueue` 再 `send_text`，避免快速停止丢最后一帧。
- **帧溯源（rule 38）**：落库帧带 `seq_no / timestamp_utc / monotonic_ms / t_seconds / sensor_path_id / sample_id`，前端 timestamp 仅显示。
- **切真实后端零改动**：改 `frontend/.env.local`（或 `config/config.ts`）指向真实地址即可，协议见 `docs/接口说明.md`。

## 6. 已实现功能清单

### 6.1 实时界面（Phase 3，F01–F10）
启动加载 / 开始停止重开状态机 / 实时 EC-温度数值（μS/cm、°C）/ 实时曲线自动追加 / WebSocket 断线 3s 提示 + 自动重连 / 坏帧不崩 / 10Hz 持续流 / 1 万点不卡（burst 验证）。

### 6.2 数据存储与导出（Phase 7）
SQLite 四表（experiments / samples / raw_frames / calibration_records）；异步落库；历史实验列表/详情/原始帧；CSV/JSON 导出；样品溯源（sample_id / sensor_path_id / 浓度可选）。

### 6.3 化学公式拟合（备选公式）
- 按 **X 轴语义** 分模型池（`x_axis`）：
  - `time`：线性 / 二次 / **一阶指数饱和** y=a−b·e^(−k·x) / 指数 / 对数 / 幂
  - `temperature`：线性温补 / 二次 / **Arrhenius** y=a·e^(−Ea/(R·T))（输出 `Ea_kJ_mol`）
  - `concentration`：线性标定 / 二次 / **Kohlrausch** y=c·(a−b·√c)（a=Λ∞、b=K）
- 纯 Python 高斯消元解正规方程，零 numpy 依赖（树莓派友好）；非线性（一阶饱和）用 k 对数网格搜索。
- 前端 `FitPanel` 为共享组件：结果区与历史详情页复用，X 轴切换、模型多选、结果表按 R² 排序、最优高亮、曲线叠加。

## 7. API 摘要（完整见 `docs/接口说明.md`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查 |
| POST | `/api/experiment/start` | 开始实验（body 可选 `sample_id/sensor_path_id/title/...`） |
| POST | `/api/experiment/stop` / `reset` | 停止 / 复位 |
| WS | `/ws/stream` | 实时数据帧（10Hz，含状态帧） |
| GET | `/api/experiments` | 历史列表 |
| GET | `/api/experiments/{id}` | 详情（含样品汇总） |
| GET | `/api/experiments/{id}/frames` | 原始帧（limit 参数） |
| GET | `/api/experiments/{id}/export.csv` / `.json` | 导出 |
| POST | `/api/analysis/fit` | 化学公式拟合（body: `x/y/models/x_axis`） |
| POST | `/api/debug/bad-frame` | 注入坏帧（验收 F10） |
| POST | `/api/debug/close-connections` | 强制断开 WS（验收 F08/F09） |
| POST | `/api/debug/burst?count=N` | 快速推 N 帧（验收 P04） |

## 11. 已知问题与踩坑记录（详见 `docs/已知问题.md`）

1. **Edge channel teardown 卡 300s**：`E2E_BROWSER=msedge` 跑完整套件，用例全过后 worker 偶发 5 分钟不退出被强杀。规避：`npx playwright install chromium` 后去掉 `E2E_BROWSER`；或跑完手动清理残留 `ec-e2e` 的 msedge/node 进程。
2. **Edge 下 `<a download>` 不触发 Playwright download 事件**：会被 Edge 下载中心接管（导航到 `edge://downloads-hub/`）。E2E 改用 `page.request.get` 断言 CSV 内容。
3. **前端 dev server 偶发挂掉**：E2E 卡在页面加载时先查 `curl localhost:5173` 是否 200；挂了用 `C:\nodejs\npm.cmd run dev` 重启。
4. **P03 30 分钟长跑**：默认跳过，需 `STABILITY_MINUTES` 显式指定；运行期探活全过，但同样受 teardown 卡顿影响。
5. **真实后端未就绪**：全部验证基于模拟源；接入时按 `docs/接口说明.md` 对齐协议。
