## 2. 执行原则（硬约束，源自 V2 回归复盘）

以下为**强制约束**，任何节点不满足不得合并：

1. **数据库 schema 变更必须事务化**：一个版本一个事务，失败整体回滚，绝不出现半迁移状态（V2 事故根因 #1）。
2. **SQLite 改列约束 = 重建表**，必须在同一事务内完成 `DROP/CREATE/COPY/RENAME`，并做**行数校验**（V2 事故根因 #2）。
3. **迁移必须幂等且可复现**：新库与旧库升级到同一版本后表结构完全一致；**先写「旧库升级」测试，再写迁移代码**（V2 事故根因 #3）。
4. **RENAME COLUMN 保留原约束**：字段语义变化时主动解除 NOT NULL / 改类型，不靠猜（V2 事故根因 #2）。
5. **垂直切片优先**：每切片独立演示、独立验收、可回滚；不做跨多个子系统的"一揽子提交"。
6. **兼容层过渡门槛**：新增目标字段 + 保留旧字段 → 数据库迁移 + E2E 全绿 → 才可废止旧标识。三步缺一不可。
7. **先复现再落盘**：硬件参数（激励频率/量程/拓扑/温补模型）先在台架复现验证，再冻结进配置与文档，不照抄器件宣传参数。
8. **不声明精度/量程/温补误差**：除非有本文件 §3 对应节点的验收证据支撑。
9. **大改动前先写旧库升级测试**：动 schema 前必须有 `v1 库 → 新库` 的自动化升级用例（V2 事故教训 #6）。
10. **每节点提交时附验收证据**：单测/集成/E2E 结果或台架数据，随 commit message 或 docs/ 记录。

| 项 | 内容 |

## 4. 数据模型与迁移安全

### 4.1 V1 现状（基线）

```text
raw_frames: experiment_id, sensor_path_id, seq_no?, timestamp, ec_raw NOT NULL, temperature_raw NOT NULL, ...
calibration_records: 表已建，未写入
帧(schemas.Frame): timestamp, ec, temperature, status   # 简化 4 字段
```

### 4.2 目标协议字段（原路线图 §4，落库时补齐）

| 分层 | 字段 | V1→目标 |
|---|---|---|
| Raw | `voltage_raw_v, current_raw_a, temperature_raw_c` | 新增；`ec_raw`→`legacy_ec_us_cm`（V2 已做过的重命名，按本文件重做时走事务化） |
| Calibrated | `voltage_cal_v, current_cal_a, conductance_s, kappa_t_us_cm` | 新增 |
| Derived | `kappa_25_us_cm, representative_value, fit_result` | 新增 |
| Trace | `seq_no, timestamp_utc, monotonic_ms, sensor_path_id, calibration_id` | `seq_no/timestamp_utc/monotonic_ms` 已具备部分 |
| Configuration | `excitation_frequency_hz, excitation_amplitude_v, range_id, compensation_model, alpha_per_c` | 新增，随实验版本化 |
| Quality | `quality_flags` | 新增（饱和/欠量程/开路/短路/温度无效/未校准/校准过期/波形不稳） |

### 4.3 迁移安全规范（V2 事故核心教训，硬性）

1. **版本化迁移 = 一个版本一个事务**：`BEGIN` → 迁移 DDL/DML → 行数校验 → 记录版本 → `COMMIT`；任一步失败 `ROLLBACK`。
2. **重建表类迁移**（改约束/加 NOT NULL 语义变更）：`DROP 旧表 → CREATE 新表 → COPY → RENAME → 重建触发器/索引 → 行数校验`，全部在一个事务内。
3. **先写「旧库升级」测试**：构造一个真实 V1 库（含数据），跑迁移到目标版本，断言表结构与数据完整性（行数、字段、抽样值）。
4. **幂等可复现**：新库 `init_db` 直建目标结构；旧库逐步迁移到同一结构；两者最终 `PRAGMA table_info` 完全一致。
5. **兼容层过渡门槛**：新增目标字段 + 保留旧字段 → 迁移 + E2E 全绿 → 才允许废止旧标识（`ec_raw`/`CM2_WIDE`）。
6. 严禁在无测试情况下执行 `RENAME COLUMN` 保留原约束后直接写新语义数据（V2 事故根因）。

## 5. 风险登记册

| # | 风险 | 等级 | 缓解 / 触发回滚判据 |
|---|---|---|---|
| R1 | 数据库迁移半途崩溃/数据损坏 | **高** | §4.3 事务化 + 旧库升级测试；任何迁移失败→整体回滚到上一版本（V2 事故验证：回退比打补丁安全） |
| R2 | 旧库升级后列状态与新库不一致 | **高** | §4.3.4 幂等断言；CI 覆盖"旧库→新库"路径 |
| R3 | 硬件器件（ADS1256/激励源/电极）不达规格 | 中 | 台架复现再冻结；不照抄器件参数（原路线图 §3） |
| R4 | 温补模型在适用温区外漂移 | 中 | 只在验证温区声明；模型版本化；验收③多温度点 |
| R5 | 判稳/QC 阈值无依据 | 中 | 先按台架数据标定再冻结 |
| R6 | 电极重复性/装夹误差破坏 Kcell | 中 | N3 验收②重复装夹 <1% |
| R7 | 前端兼容层破坏旧 UI | 低 | §2.6 三步过渡门槛；E2E 全绿才废止 |
