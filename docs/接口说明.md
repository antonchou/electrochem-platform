# 接口说明（交付物 #4）

## 1. WebSocket 实时数据流

- **地址**：`ws://<host>:8000/ws/stream`
- **协议**：UTF-8 JSON
- **速率**：实验运行期间 ≥1Hz（模拟源为 10Hz）

### 数据帧

```json
{
  "message_type": "measurement",
  "schema_version": "2.0",
  "experiment_uid": "EXP-20260822T120000-abcd",
  "seq_no": 124,
  "timestamp_utc": "2026-08-22T12:00:12.350000Z",
  "monotonic_ms": 12350,
  "t_seconds": 12.35,
  "voltage_raw_v": 0.4,
  "current_raw_a": 0.000565,
  "temperature_raw_c": 25.3,
  "conductance_s": 0.0014125,
  "kappa_t_us_cm": 1412.5,
  "kappa_25_us_cm": 1404.1,
  "excitation_frequency_hz": 1000,
  "excitation_amplitude_v": 0.4,
  "range_id": "R_100R_10K",
  "sensor_path_id": "EC_IV_CELL_MOCK",
  "calibration_id": "CAL_MOCK_CONFIG",
  "cell_constant_cm_inv": 1.0,
  "calibration_valid_until_utc": null,
  "compensation_model": "linear",
  "alpha_per_c": 0.02,
  "quality_flags": ["SIMULATED"],
  "status": "running"
}
```

| 字段 | 类型 | 单位 | 含义 |
|---|---|---|---|
| `message_type` | string | — | `measurement`（测量/质量帧） |
| `experiment_uid` | string | — | 当前实验稳定标识，用于重连后隔离新旧缓冲 |
| `t_seconds` | number | s | 实验开始后的时间（float） |
| `voltage_raw_v` / `current_raw_a` / `temperature_raw_c` | number? | V / A / °C | 不可变 Raw；DROPOUT 时可缺失 |
| `conductance_s` / `kappa_t_us_cm` | number? | S / μS/cm | 校准计算层 |
| `kappa_25_us_cm` | number? | μS/cm | 温补结果；未校准/温补不可用时缺失 |
| `calibration_id` / `cell_constant_cm_inv` | string? / number? | — / cm⁻¹ | 校准标识与 Kcell；每帧保存用于回算追溯 |
| `quality_flags` | string[] | — | 未校准、掉点、越界等质量标志；正常时也保留数组键 |
| `status` | string | — | `idle`/`running`/`stopped`/`error` |

### 状态广播帧

某些时刻（开始/停止/重置）服务端会推送状态帧：

```json
{ "message_type": "status", "status": "stopped", "experiment_uid": "EXP-..." }
```

前端严格按 `message_type` 分流。实时 measurement 必须是 `schema_version=2.0` 且包含 Raw、Calibrated、Derived、Configuration、Trace、Quality 各层键；缺值显式为 `null`。缺少 `message_type` 的 V1 帧会被拒绝，不进入实时缓冲。

### 异常处理约定

- 非法 JSON、缺字段、`NaN`、未知 `status` → 前端**丢弃该帧并提示**，页面不崩溃。
- 断线 → 3 秒内提示「已断开/重连中」，并自动重连（指数退避 ≤5s）。
- 连接存活但 3 秒无数据 → 提示「数据流超时」。

## 2. REST 控制接口

基础地址：`http://<host>:8000`

| 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|
| POST | `/api/experiment/start` | `{sample_id?, sensor_path_id?, title?, operator?, objective?, concentration_mmol_l?, calibration_id?, cell_constant_cm_inv?, alpha_per_c?, compensation_model?, excitation_frequency_hz?, excitation_amplitude_v?, range_id?}` | `{ok, status, experiment_id?, sample_id?}` |
| POST | `/api/experiment/stop` | — | `{ok: true, status: "stopped", experiment_id}` |
| POST | `/api/experiment/reset` | — | `{ok: true, status: "idle"}` |
| GET | `/health` | — | `{status: "ok", experiment: "idle"}` |

> `start` 请求体为**可选**（Phase 7 样品溯源）。不传时使用默认样品 `SAMPLE` 和 Mock V2 链路 `EC_IV_CELL_MOCK`；真实硬件应使用 `EC_IV_CELL_<编号>`。提供 Kcell 时必须同时有 `calibration_id`。
> 校准参数省略时使用设备配置默认；显式传 `cell_constant_cm_inv: null` 会强制未校准，Raw 帧仍保存并标记 `UNCALIBRATED`。

响应统一为：

```json
{ "ok": true, "status": "running", "message": null, "experiment_id": 12, "sample_id": "NACL_004" }
```

- `ok=false` 表示操作无效（如运行中重复 start），`message` 为原因。
- 错误码：`4xx`（客户端错误）/ `5xx`（服务端错误）；前端应捕获异常并给出可理解提示。

## 2.5 历史查询与导出（Phase 7）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/experiments` | 历史实验列表（含每实验 `frame_count`） |
| GET | `/api/experiments/{id}` | 实验详情：元信息 + `samples[]` 样品汇总 |
| GET | `/api/experiments/{id}/frames?limit=&offset=` | 原始帧分页（字段见下） |
| GET | `/api/experiments/{id}/export.csv` | 导出原始帧 CSV（Excel 可打开，`Content-Disposition: attachment`） |
| GET | `/api/experiments/{id}/export.json` | 导出完整实验（元信息 + 全部帧）JSON |

帧字段包括：`seq_no, timestamp_utc, monotonic_ms, t_seconds, sensor_path_id, sample_id, legacy_ec_us_cm, temperature_raw_c, voltage_raw_v, current_raw_a, conductance_s, kappa_t_us_cm, kappa_25_us_cm, excitation_frequency_hz, excitation_amplitude_v, range_id, calibration_id, cell_constant_cm_inv, calibration_valid_until_utc, compensation_model, alpha_per_c, quality_flags, status`。

其中 U/I/T 属 Raw，G/κ(T) 属 Calibrated，κ25 属 Derived；`legacy_ec_us_cm` 仅为 V1 `ec`（=κ(T)）迁移列，不是硬件原始量。详细定义见 `docs/电导率I-V测量链路与开发路线.md`。

数据约束（REQ-D-001）：`raw_frames` 为 **append-only**，服务端触发器禁止 `UPDATE`/`DELETE`，原始数据不可篡改；导出即取证。

## 2.6 备选公式拟合

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/analysis/fit` | 对数据点做化学备选公式拟合，按 R² 排序返回参数与拟合曲线 |

请求体：

```json
{
  "x": [0.0, 0.1, 0.2],
  "y": [1413.1, 1413.0, 1412.9],
  "models": ["linear", "quadratic"],
  "x_axis": "time"
}
```

- `x`/`y` 等长且 ≥3 个点；`models` 缺省为该轴全部模型。
- **`x_axis`** 标明 X 轴物理含义，决定化学模型池：
  - `time`（默认，EC-时间）：`linear`、`quadratic`、`first_order`（一阶指数饱和 y=a−b·e^(−k·x)）、`exponential`（y=a·e^(b·x)，要求 y>0）、`logarithmic`（y=a+b·ln(x)，要求 x>0）、`power`（y=a·x^b，要求 x>0,y>0）
  - `temperature`（EC-温度 °C）：`linear`（线性温补）、`quadratic`、`arrhenius`（Arrhenius y=a·e^(−Ea/(R·T))，T=x+273.15，输出 `Ea_kJ_mol`，要求 y>0）
  - `concentration`（EC-浓度）：`linear`（线性标定）、`quadratic`、`kohlrausch`（Kohlrausch κ=κblank+Λ0·c−K·c^1.5，要求至少 3 个不同且 c>0 的真实浓度；前端不会用样本序号代替浓度）
  - 跨轴模型会被忽略（如 temperature 轴下请求 `kohlrausch`）。
- 响应：`{ best, models: [{model, label, params, r2, rmse, n, fitted}] }`，`fitted` 为 150 个采样点的拟合曲线。

## 3. 调试接口（仅模拟源，验收用）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/debug/bad-frame` | 注入数值合法但无 `message_type` 的 V1 帧，验证在线端拒绝降级（F10） |
| POST | `/api/debug/close-connections` | 强制断开所有 WS（验证 F08/F09） |
| POST | `/api/debug/burst?count=10000` | 快速推 N 帧（验证 P04 万点负载） |

> 真实后端无需提供调试接口。
