## 1. 总览与基础约定

### 1.1 架构与数据流

```text
数据源（Mock / Simulator / CSV 回放 / 未来真实硬件）
   → DeviceDriver.read(elapsed) → DriverReading（Raw：U/I/T + quality_flags）
   → measurement.compute_chain（G = I/U → κ(T) → κ25）
   → 组帧 _build_frame（Raw + Derived + 溯源 + V1 兼容别名）
   → 单一采集循环（10 Hz 缺省）：SQLite 批量落库（append-only）＋ WebSocket 广播
   → 前端（React）：实时曲线 / 控制 / 历史查询 / 导出 / 拟合
```

关键架构事实（影响接口语义）：

- **采集与连接数无关**：后台只有一个采集任务（P1-1），running 期间无论有无浏览器连接都持续采数、落库；所有 WebSocket 客户端收到的是同一套广播帧。
- **落库与广播解耦**：帧写入走异步队列（攒批 ≤200 条或 0.5 s），不阻塞实时流；批量写入失败进入「持久化降级」状态（见 §2.5）。
- **Raw 不可变**：`raw_frames` 表由触发器强制 append-only，`UPDATE`/`DELETE` 直接报错（REQ-D-001）。

### 1.2 基础约定

| 项 | 约定 |
|---|---|
| 基础地址 | 开发：`http://localhost:8000`；生产：FastAPI 同源托管 `frontend/dist`（端口由部署决定，`EC_BIND`/`EC_PORT` 见 §7） |
| 实时流 | `ws://<host>:8000/ws/stream`（HTTPS 环境为 `wss://`） |
| 编码 | 全部 JSON 为 UTF-8；CSV 导出 `text/csv; charset=utf-8` |
| 时间字段 | 相对时间 `timestamp`/`t_seconds`（秒，实验开始后，暂停不计时）；墙钟 `timestamp_utc`（`%Y-%m-%dT%H:%M:%S.%fZ`，UTC）；单调钟 `monotonic_ms` |
| 电导率单位 | μS/cm（κ25 规范名 `kappa_25_us_cm`，旧列/别名 `k25`、`ec`，三者差别与取用规则见 §4.2.1）；`1 S/cm = 1e6 μS/cm` |
| CORS | 显式白名单 `EC_CORS_ORIGINS`；缺省正则放行 `localhost` / `127.0.0.1` / `10.x` / `192.168.x` / `172.16–31.x` / `*.local` 任意端口（教室局域网演示策略） |
| 写请求 Origin 校验 | 非 GET/HEAD/OPTIONS 请求带 `Origin` 时，只放行同源与上面的 CORS 放行范围，其余 403 `{"detail": "拒绝跨站请求"}`；不带 `Origin`（curl、脚本）放行。CORS 拦不住浏览器的简单请求（如无请求体的 `stop`/`reset`），由这一层防跨站触发 |
| OpenAPI | FastAPI 自动生成：`GET /docs`（Swagger UI）、`GET /openapi.json`（REST 部分权威 schema） |
| 版本号 | 应用版本单一来源 `backend/app/__init__.py`（当前 `1.0.0`）；帧协议版本 `schema_version = 2`；库结构版本 `SCHEMA_VERSION = 6` |

### 1.3 实验状态机

内存态 `status`（接口层可见）：`idle → running → stopped → running（续跑）…`，`reset` 回到 `idle`。

数据库 `experiments.status`（终态）：`running / stopped / aborted / error`。

| 操作 | 内存态变化 | 数据库变化 |
|---|---|---|
| start（idle） | idle → running | 新建 `experiments(status=running)` + 首个 `samples` 行（同一事务）+ `calibration_records`（有校准编号时，见 §3.1） |
| start（stopped，同样品） | stopped → running（续跑） | `reopen_experiment`：status 回 `running`、清 `ended_at_utc`；**seq_no 续接** |
| start（stopped，换样品）或 idle 再 start | → running | 新建实验记录 |
| start（running） | 不变 | 无；响应 `ok=false` |
| stop（running） | running → stopped | flush 帧队列 → 计算判稳 QC 写入 `samples` → `finish_experiment(stopped)` |
| reset | 任意 → idle | 若运行中：`finish_experiment(aborted)`；内存上下文全部清空 |
| 进程启动 | 恒 idle | 遗留 `running` 行一次性标记 `aborted` |
| 进程关闭时仍在运行 | — | flush 后 `finish_experiment(aborted)`，关闭全部 WS（close code 1001） |

> 注意：`error` 是合法的枚举值（前端解析层接受），当前代码**不会主动下发** `status: "error"` 的帧；数据库侧仅在 start 事务失败回滚时可能出现 `error` 终态行。

## 2. WebSocket 实时数据流 `/ws/stream`

### 2.1 连接与生命周期

- 连接即订阅：`connect` 后自动加入广播集合，服务端**不等待任何订阅消息**；客户端发来的文本会被读取但**没有业务语义**（仅作为断连检测）。
- 服务端消息分两类：**数据帧**（含 `timestamp`/`temperature`/`ec` 任一即数据帧）与**状态帧**（只含 `status` 等，见 §2.4）。前端判别方式：无 `timestamp`/`ec`/`temperature` 字段 → 状态帧。
- 消息频率：实验 running 期间按驱动采样率推送（缺省 10 Hz；任务书下限 ≥1 Hz）；idle/stopped 期间**没有周期数据**，只有状态帧。
- 慢客户端隔离（`BroadcastHub`）：每个连接独立有界队列（20 000 条），队满丢**最旧**帧，不阻塞采集；丢帧由客户端自行通过 `t_seconds` 断档感知。
- 服务端主动关闭：进程关停 close code **1001**（"server shutdown"）；调试接口强制断开也是 1001；发送任务异常时 **1011**。
- 采集节拍按截止时刻调度，平均速率贴合配置采样率；落后超过一个周期时从当前时刻重新对齐，不补发积压周期。
- 读数持续抛错（如 ADC 掉线）时采集任务不退出：指数退避重试（上限 5 s），每段失败首次向前端广播一条告警状态帧（见 §2.4），恢复后继续出帧。

### 2.2 数据帧（running 期间 10 Hz）

来源 `acquisition._build_frame`。V1 兼容字段 `timestamp / ec / temperature / status` 恒在；I–V 链路字段（`schema_version = 2`）在驱动提供 U/I/T 时下发。

```json
{
  "timestamp": 12.34,
  "ec": 1415.3,
  "temperature": 25.05,
  "status": "running",
  "quality_flags": "SIMULATED",
  "schema_version": 2,
  "device_id": "MOCK-IV-01",
  "firmware_version": "0.1.0",
  "range_id": "WIDE",
  "calibration_id": "MOCK-KCELL-1.0",
  "excitation_frequency_hz": 1000.0,
  "excitation_amplitude_v": 1.0,
  "compensation_model": "linear_alpha",
  "voltage_raw_v": 1.000123,
  "current_raw_a": 0.0014169,
  "temperature_raw_c": 25.05,
  "conductance_s": 0.0014167,
  "kappa_t_us_cm": 1416.7,
  "kappa_25_us_cm": 1415.3,
  "experiment_id": 12
}
```

| 字段 | 类型 | 单位 | 含义 / 约定 |
|---|---|---|---|
| `experiment_id` | number | — | 所属实验（DB 自增 id）。有实验上下文时每帧都带（含 V1 简化帧）；前端实时缓冲据此隔离实验（id 与缓冲归属不同即先清空）。调试 burst 帧不带 |
| `timestamp` | number | s | 实验开始后的相对时间，保留 2 位小数；暂停期间冻结，续跑从停点续上 |
| `ec` | number \| null | μS/cm | **V1 兼容别名 = κ25**，保留 1 位小数；计算链拒绝时为 `null`（合法，见 §2.3） |
| `temperature` | number | °C | 溶液温度（= `temperature_raw_c` 兼容别名） |
| `status` | string | — | 数据帧恒为 `"running"` |
| `quality_flags` | string \| null | — | `\|` 分隔质量标志，见 §6 |
| `schema_version` | number | — | 协议版本，当前 `2` |
| `device_id` | string | — | 设备/数据源标识，取自驱动 config（Mock：`MOCK-IV-01`，Simulator：`SIM-IV-01`，CSV：`CSV-PLAYBACK-01`；未声明时 `UNKNOWN`，见 §7.1） |
| `firmware_version` | string | — | 数据源声明固件版本 |
| `range_id` | string | — | 量程档位（Mock `WIDE` / Simulator `SIM` / CSV `CSV`） |
| `calibration_id` | string \| null | — | 关联 `calibration_records`；未校准哨兵值 `"UNCALIBRATED"` |
| `excitation_frequency_hz` | number | Hz | 激励频率（Mock/Sim 缺省 1000；CSV 缺省 0 = 直流） |
| `excitation_amplitude_v` | number | V | 激励幅值（驱动 config 同名字段；Mock 用它作受控激励电压 U） |
| `compensation_model` | string | — | 温补模型标识，当前恒 `linear_alpha` |
| `voltage_raw_v` | number | V | Raw：激励实测电压 U |
| `current_raw_a` | number | A | Raw：回路电流 I |
| `temperature_raw_c` | number | °C | Raw：温度 T |
| `conductance_s` | number \| null | S | Derived：G = I/U |
| `kappa_t_us_cm` | number \| null | μS/cm | Derived：κ(T) = Kcell·G·1e6 |
| `kappa_25_us_cm` | number \| null | μS/cm | Derived：κ25 温补折算（= `ec`） |

**帧生成规则**（决定哪些字段会出现）：

1. **I–V 完整帧**（U/I/T 齐备）：走计算链，全字段下发；计算链抛 `ValueError`（U ≤ 0、温补分母为 0 等）时 → Derived 三字段与 `ec` 为 `null`，`quality_flags` 追加 `COMPUTE_INVALID`，Raw U/I/T 照常下发落库。
2. **V1 简化帧**（仅 ec/T 齐备的旧式驱动）：只有 `timestamp/ec/temperature/status/quality_flags`，无 v2 字段。
3. **不完整读数**（如 dropout 帧 U/I/T/ec 均缺，或任一读数为 NaN/inf——例如温度探头读失败）：**不广播、不落库**，客户端只表现为时间轴断档。
4. **续跑边界重复帧**：续跑后的首帧若与停止前最后一条落库帧的 U/I/T 完全相同（CSV 等确定性源重采样了边界行），丢弃：不占 `seq_no`、不落库、不广播。

### 2.4 状态帧

只含 `status`（可带 `experiment_id` / `sample_id` / `message` / `persistence`），在生命周期切换或告警时广播：

| 触发时机 | 载荷 |
|---|---|
| start 成功（含续跑） | `{"status": "running", "experiment_id": 12, "sample_id": "NACL_004"}` |
| stop（确有 running→stopped） | `{"status": "stopped", "experiment_id": 12, "sample_id": "NACL_004"}`（降级时附加 `message` + `persistence`） |
| reset | `{"status": "idle"}`（降级时附加 `message` + `persistence`） |
| 采集读数连续失败（每段失败首次广播一次） | `{"status": "running", "message": "采集异常：设备读数失败，正在自动重试（详见后端日志）。", "experiment_id": 12?}` |
| 持久化降级告警（首次拒帧时广播一次） | `{"status": "<当前态>", "message": "落库失败：实时曲线仍在更新，但历史和导出将缺帧。请重启后端恢复落库。", "persistence": "degraded", "experiment_id": 12?}` |
| WebSocket 连接建立时若已处于降级 | 同上，仅发给该新连接 |

前端处理约定：状态帧只更新状态，不追加数据点；带 `sample_id` 时旁观端（其它浏览器）据此更新溶液名；带 `message` 时显示为提示横幅。

### 2.5 持久化降级语义

- 批量落库失败 → `persist.degraded = true`，**后续帧全部拒收**（防内存无限增长）。
- 被拒收的帧**仍然广播**，但 `quality_flags` 追加 `PERSIST_DROPPED`（该帧不会出现在历史/导出中）。
- 降级告警状态帧在同一次降级中只主动广播一次；新连接会补发。
- 恢复方式：重启后端进程（重新走 lifespan 初始化）。

### 2.6 客户端健壮性约定（与前端实现一致）

- 非法 JSON、缺 `timestamp`/`temperature`、数值型字段含非有限值、未知 `status` → 丢弃该帧并提示，页面不崩溃。`ec: null` 是**合法**数据帧。
- 数值字段允许字符串形式（`"1412.8"`），解析层统一 `Number()` 归一。
- 断线：3 s 内提示「已断开 / 重连中」，自动重连按指数退避 1 s, 2 s, 4 s, … 截断 5 s；连接恢复后拉 `GET /api/experiment/current` 对齐所属实验与样品号。
- 运行中连接存活但 3 s 无任何消息 → 提示「数据流超时」（仅 running 时检查，避免空闲误报）。

## 3. REST 接口

统一约定：请求/响应 JSON（导出接口除外）；业务失败（如重复 start）**不返回 4xx**，而是 `200 + ok=false + message`；参数校验失败由 Pydantic 返回 **422**；资源不存在返回 **404** `{"detail": "..."}`。

### 3.1 实验控制

| 方法 | 路径 | 请求体 | 说明 |
|---|---|---|---|
| POST | `/api/experiment/start` | 可选，见下 | 开始/续跑实验 |
| POST | `/api/experiment/stop` | 无 | 停止并触发判稳 QC、落终态 |
| POST | `/api/experiment/reset` | 无 | 清空当前实验上下文回 idle |

**start 请求体**（`ExperimentStartRequest`，全部字段可选；字符串字段原样入库/导出，故限长）：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `sample_id` | string \| null | ≤64 字符 | 样品编号；缺省 `SAMPLE` |
| `sensor_path_id` | string \| null | ≤64 字符 | 测量链路标识；缺省 `MOCK_EC_IV`。旧标识 `CM2_WIDE` 仍可显式传入，不代表正式硬件采用 CM2；真实链路 ID 应改为 `EC_IV_CELL_<编号>` |
| `title` | string \| null | ≤200 字符 | 实验标题；缺省「不同溶液导电性相对比较」 |
| `operator` | string \| null | ≤64 字符 | 操作人 |
| `objective` | string \| null | ≤500 字符 | 实验目的 |
| `concentration_mmol_l` | number \| null | 0 ≤ x ≤ 10000 | 标称浓度 mmol/L，写入 `samples`（浓度轴拟合需要） |

**start 语义（重点）**：

- stopped 状态下**不传 `sample_id` = 沿用当前样品 = 续跑**（`resumed: true`）。因此「省略参数开新实验」不可行——开新实验必须显式传新 `sample_id`，或先 `reset`。前端「重新开始」按钮即 `reset` + `start`。
- 续跑时同一 DB 记录重新打开，`seq_no` 从停点续接；确定性数据源（CSV）的边界重复帧会被去重（比较停止前最后落库帧的 U/I/T 三元组，仅判续跑首帧）。
- 新实验 start 时写入一条 `calibration_records`：`calibration_id` 取 `EC_CALIBRATION_ID` 环境变量，否则取驱动 config 的 `calibration_id`（Mock `MOCK-KCELL-1.0`、Simulator `SIM-KCELL-1.0`、CSV `UNCALIBRATED`）；两者都为空则不写。`mode` 为 `cell_constant`（已校准）或 `none`，`coeff_value` 仅已校准时填电池常数。续跑不重复写。

**ControlResponse**（三个控制接口共用）：

```json
{
  "ok": true,
  "status": "running",
  "message": null,
  "experiment_id": 12,
  "sample_id": "NACL_004",
  "resumed": false,
  "persistence": null
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | boolean | `false` = 操作无效（如运行中重复 start，`message` 给出原因「实验已在进行中」） |
| `status` | string | 操作后内存态：`running` / `stopped` / `idle` |
| `message` | string \| null | 失败原因或降级提示 |
| `experiment_id` | number \| null | **数据库自增 id**（历史/导出接口用它；区别于字符串 `experiment_uid` 如 `EXP-20260923T103000-a1b2`） |
| `sample_id` | string \| null | 当前样品编号（start 时） |
| `resumed` | boolean \| null | 仅 start：true = 续跑同一实验 |
| `persistence` | string \| null | `"degraded"` 表示落库已降级 |

幂等性：重复 `stop` / 任意时刻 `reset` 均返回 `ok=true`（不带 message，前端不当作失败）。

### 3.2 当前实验 `GET /api/experiment/current`

前端刷新/重连后恢复 `experiment_id` 与导出入口用：

```json
{
  "status": "stopped",
  "experiment_id": 12,
  "sample_id": "NACL_004",
  "experiment_uid": "EXP-20260923T103000-a1b2",
  "persistence": "ok",
  "message": null
}
```

无实验上下文时 `experiment_id / sample_id / experiment_uid` 为 `null`（`sample_id` 在 reset 后恒为 `null`，不回显默认值）。

### 3.3 健康检查 `GET /health`

```json
{ "status": "ok", "experiment": "running", "persistence": "ok", "persistence_error": null }
```

`persistence`：`"ok"` | `"degraded"`；`persistence_error` 为降级时的异常文本。

### 3.4 历史查询

| 方法 | 路径 | 参数 | 响应 |
|---|---|---|---|
| GET | `/api/experiments` | — | `ExperimentSummary[]`，按 id 倒序，含 `frame_count` 与主样品摘要 |
| GET | `/api/experiments/{exp_id}` | — | 实验详情（见下），不存在 → 404 |
| GET | `/api/experiments/{exp_id}/frames` | `limit`（1–100 000，缺省 1000）、`offset`（≥0，缺省 0）、`mode`（`head` 缺省 / `tail` / `even`） | `{"frames": RawFrame[], "total": N, "mode": "head"}`，帧按时间正序 |

**frames 的 `mode`**：

- `head`：按落库顺序从 `offset` 起取 `limit` 条（分页）。
- `tail`：最新 `limit` 条（仍按时间正序）；前端续跑水合用 `mode=tail&limit=20000`。

- `offset` 只能与 `head` 同用，否则 400。`total` 为该实验总帧数。

### 3.6 备选公式拟合 `POST /api/analysis/fit`

**请求体**（`FitRequest`）：

```json
{
  "x": [0.0, 0.1, 0.2],
  "y": [1413.1, 1413.0, 1412.9],
  "models": ["linear", "quadratic"],
  "x_axis": "time",
  "experiment_id": 12
}
```

| 字段 | 约束 | 说明 |
|---|---|---|
| `x` / `y` | 等长，3 ≤ n ≤ 20 000，且全部有限数值 | 不等长或含非有限值 → 400；点数 <3 或 >20 000 → 422（Pydantic 先校验） |
| `models` | string[]，可选 | 缺省 = 该轴全部模型；**跨轴模型被静默忽略**；显式 `[]` = 不运行任何模型 |
| `x_axis` | `time` \| `temperature` \| `concentration` | X 轴物理含义，决定模型池；缺省 `time` |
| `experiment_id` | number，可选 | 提供且存在 → 本轮拟合写入 `fit_results`（先 DELETE 同 experiment+axis 旧记录）并写报告到 `data/derived/experiment_{id}_fit_{axis}.json`；不存在 → 404 |

**模型池**（`x_axis` → 可用模型与参数）：

| x_axis | model | 表达式 | params 键 | 前置条件 |
|---|---|---|---|---|
| time | `linear` | y = a + b·x | a, b | — |
| time | `quadratic` | y = a + b·x + c·x² | a, b, c | — |
| time | `first_order` | y = a − b·e^(−k·x) | a, b, k | — |
| time | `exponential` | y = a·e^(b·x) | a, b | y > 0 |
| time | `logarithmic` | y = a + b·ln(x) | a, b | x > 0 |
| time | `power` | y = a·x^b | a, b | x > 0 且 y > 0 |
| temperature | `linear` | 线性温补 y = a + b·T | a, b | — |
| temperature | `quadratic` | y = a + b·T + c·T² | a, b, c | — |
| temperature | `arrhenius` | y = a·e^(−Ea/(R·T))，T=x+273.15 | a, Ea_kJ_mol | y > 0，≥3 个不同温度且跨度 ≥1 °C |
| concentration | `linear` | 线性标定 y = a + b·c | a, b | — |
| concentration | `quadratic` | y = a + b·c + q·c² | a, b, **q** | — |
| concentration | `kohlrausch` | y = a + b·c − K·c^1.5 | a, b, K | c ≥ 0（c = 0 空白样是 κblank 锚点） |

**响应**（`FitResponse` + `derived_path`）：

```json
{
  "best": "linear",
  "models": [
    {
      "model": "linear",
      "label": "线性 y = a + b·x",
      "params": {"a": 1413.05, "b": -0.02},
      "r2": 0.987,
      "rmse": 0.41,
      "mae": 0.33,
      "aicc": 12.7,
      "n": 300,
      "fitted": [[0.0, 1413.05], [0.067, 1413.04]],
      "x_min": 0.0,
      "x_max": 20.0,
      "extrapolation_forbidden": true,
      "residual_max_abs": 0.9,
      "param_ci": {"a": [1412.9, 1413.2], "b": [-0.03, -0.01]},
      "loocv_rmse": 0.43
    }
  ],
  "derived_path": "D:\\...\\data\\derived\\experiment_12_fit_time.json"
}
```

- `models` 按 **R² 从高到低**排序；`best` = 首个（全失败时 `null`，`models: []`）。
- `fitted`：区间内 **150 个**等间隔采样点 `[x, y]`（x 跨度 < 1e-9 时 1 个点）；**禁止外推**超出 `[x_min, x_max]`（`extrapolation_forbidden` 恒 true）。
- `param_ci`：95% Wald CI，仅对线性于参数的模型输出（linear / quadratic / logarithmic / kohlrausch）；样本数 ≤ 参数数或矩阵奇异时为 null。
- `loocv_rmse`：留一交叉验证 RMSE，仅 4 ≤ n ≤ 60 时计算；`first_order` 不算（网格搜索代价高）。
- y 恒定（相对波动 < 1e-6）视为退化数据，该模型跳过；含 NaN/±inf 的结果整模型拒绝（避免 500）。
- 空拟合结果**不落库、不覆写** derived 报告（防止失败拟合清空历史）。
- 单个实验只有一种浓度，前端在单实验里禁用浓度轴拟合；多浓度标定用 §3.7 的跨实验标定。

### 3.7 跨实验浓度标定 `POST /api/analysis/calibration`

一实验一点：每个实验取主样品的 κ25 代表值与浓度，按浓度轴模型池拟合。取点在服务端从库里读，不信任前端传值。

**请求体**（`CalibrationRequest`）：

```json
{ "experiment_ids": [21, 22, 23], "models": ["linear", "kohlrausch"] }
```

| 字段 | 约束 | 说明 |
|---|---|---|
| `experiment_ids` | number[]，3–200 个 | 超出范围 → 422；重复 id 去重 |
| `models` | string[]，可选 | 缺省 = 浓度轴全部模型（`linear` / `quadratic` / `kohlrausch`） |

**准入**（任一实验不满足 → 整体 400，`detail` 用「；」列出每个不合格实验的原因，而不是悄悄少点）：

- 实验存在且 `status = stopped`；
- 主样品填了 `concentration_mmol_l`；
- QC 为 `PASS` 或 `WARN`（FAIL / 未判定不能作标定点）；
- y 取值：QC PASS 且有代表值 → `representative_value`（`source: "representative"`）；否则取窗口中位数 `k25_median`（`source: "median"`）；无可用有限值 → 不合格。

去重后不同浓度少于 3 个 → 400 `跨实验标定至少需要 3 个不同浓度`。

**响应**：

```json
{
  "best": "linear",
  "models": [ "…同 §3.6 FitResultItem…" ],
  "points": [
    {
      "experiment_id": 21,
      "experiment_uid": "EXP-20260930T101500-3f2a",
      "sample_id": "BLANK",
      "concentration_mmol_l": 0.0,
      "kappa25_us_cm": 2.1,
      "source": "representative",
      "qc_status": "PASS"
    }
  ],
  "derived_path": "D:\\...\\data\\derived\\calibration_1a2b3c4d5e6f.json"
}
```

- 报告写 `data/derived/calibration_<成员 id 排序后 SHA-1 前 12 位>.json`（含 `kind`、`created_at_utc`、成员实验、点集与拟合结果，可溯源）；同一组实验（与顺序无关）覆写同一文件。拟合全部失败时不写报告，`derived_path` 为 null。
- 不写 `fit_results` 表（该表按单实验归档）。
- 前端入口：「历史实验」→「跨实验标定」，勾选实验后在浓度轴拟合面板中运行。

### 3.8 调试接口（仅验收/测试用）

需环境变量 `EC_ENABLE_DEBUG_ENDPOINTS ∈ {1, true, yes, on}`，否则一律 **404**（对生产隐藏）。真实硬件后端不需要提供这些接口。

| 方法 | 路径 | 参数 | 行为 / 响应 |
|---|---|---|---|
| POST | `/api/debug/bad-frame` | — | 广播一条 `ec: "abc"` 非法帧（验 F10 前端容错）→ `{"ok": true, "injected": "bad-frame"}` |
| POST | `/api/debug/close-connections` | — | 以 close code 1001 断开全部 WS（验 F08/F09 重连）→ `{"ok": true, "closed": N}` |
| POST | `/api/debug/burst` | `count`（1–10 000，缺省 10 000） | 快速广播 count 帧（验 P04 负载）；**仅广播，不落库、不占 seq** → `{"ok": true, "sent": M}` |

burst 帧由 `routes._burst_frame` 生成，是 V1 简化帧：`{"timestamp", "ec", "temperature", "status": "running"}`，κ25 ≈ 1413 μS/cm + 缓慢漂移 + 噪声，**无** U/I 字段、**无** `experiment_id`；每 200 帧让出一次事件循环，避免拖慢采集。

## 4. 数据模型与存储（SQLite）

- 路径：`data/raw/ec.db`（仓库约定：原始数据不入 Git），可用 `EC_DB_PATH` 覆盖；WAL 模式；`foreign_keys = ON`。
- 结构版本：`SCHEMA_VERSION = 6`，由 `init_db()` 幂等迁移（`schema_migrations` 表记录已应用版本；每版本独立事务，失败整体回滚）。

### 4.1 表关系

```text
experiments (1) ──< raw_frames (N)        append-only 触发器
experiments (1) ──< samples (N)           UNIQUE(experiment_id, sample_id, sensor_path_id)
experiments (1) ──< calibration_records (N)
experiments (1) ──< fit_results (N)       UNIQUE 语义：同 (experiment_id, x_axis) 每轮覆写
schema_migrations                          版本登记
```

### 4.2 列清单

**experiments**：`id`（PK 自增，即接口里的 `experiment_id`）、`experiment_id`（业务 UID 字符串，UNIQUE，格式 `EXP-<YYYYmmddTHHMMSS>-<4hex>`）、`title`、`operator`、`objective`、`started_at_utc`、`ended_at_utc`、`status`（running/stopped/aborted/error）、`sample_id`、`sensor_path_id`、`metadata_json`。

**samples**：`id`、`experiment_id`、`sample_id`、`sensor_path_id`、`concentration_mmol_l`、`composition`、`preparation_record_id`、`measured_at_utc`、`k25_median`、`k25_mean`、`k25_sd`、`frame_count`（落库时自动累加）、`qc_status`、`qc_reason`、`representative_value`、`qc_checked_at_utc`（后四列 v3+）。

**raw_frames**（v1 基线 + v2 计算链 + v5 溯源）：

| 组 | 列 |
|---|---|
| 溯源 | `id`、`experiment_id`（FK）、`sample_id`、`sensor_path_id`（NOT NULL）、`seq_no`（实验内单调递增，从 1 起）、`timestamp_utc`、`monotonic_ms`、`t_seconds`、`inserted_at_utc` |
| Raw | `ec_raw`（旧直读列，v4 起可空；新帧里是 κ25 的 1 位小数副本，见 §4.2.1）、`temperature_raw`（NOT NULL）、`voltage_raw_v`、`current_raw_a` |
| Derived | `k25`（κ25 兼容列，见 §4.2.1）、`conductance_s`、`kappa_t_us_cm`、`kappa_25_us_cm`（**规范列**） |
| 质量 | `quality_flags`、`status` |
| 协议元数据（v5+） | `schema_version`、`device_id`、`firmware_version`、`range_id`、`calibration_id`、`excitation_frequency_hz`、`excitation_amplitude_v`、`compensation_model` |

append-only 约束：`BEFORE UPDATE` / `BEFORE DELETE` 触发器 `RAISE(ABORT)` —— **任何**试图改写历史帧的操作（含未来迁移）都会失败。

#### 4.2.1 κ25 的三列：以 `kappa_25_us_cm` 为准

`raw_frames` 里有三列与 κ25 有关。它们来历不同，**并不完全等值**：

| 列 | I–V 计算链的帧（v2 起） | 旧帧 / 只给 `ec` 的驱动 | 计算链拒绝的帧（`COMPUTE_INVALID`） |
|---|---|---|---|
| `kappa_25_us_cm`（**规范列**） | 软件计算链的 κ25，全精度 | NULL | NULL |
| `k25`（兼容列） | 与 `kappa_25_us_cm` 相同 | NULL | NULL |
| `ec_raw`（旧直读列） | κ25 四舍五入到 0.1 µS/cm（即实时帧的 `ec` 别名） | 驱动 / 电导率模块报的 EC，**是这类行唯一的电导率值** | NULL |

取用规则：

- **新代码与定量分析一律读 `kappa_25_us_cm`**。停止判稳（`stability.qc_from_frames`）只读这一列，`samples.k25_median / k25_mean / k25_sd` 与代表值都由它算出；实时帧同理，新代码读 `kappa_25_us_cm` 而不是 `ec`。
- `k25`、`ec_raw`（以及实时帧的 `ec`）只为旧库、旧导出格式（CSV 的 `k25_us_cm`、`ec_raw_us_cm`）和已有脚本保留，新功能不要读它们。
- 要兼顾旧数据时，**展示**可按 `kappa_25_us_cm → k25 → ec_raw` 依次回退（前端 `lib/ivAnalysis.ts` 的 `rawFrameToPoint` 即此顺序）。回退到 `ec_raw` 拿到的是旧的直读 EC，不是软件计算链的结果，与 κ25 放在一起做拟合或统计时要单独看待。
- 写入照旧：新帧三列都写（`k25`、`ec_raw` 由 `acquisition._ROW_FIELD_FROM_FRAME` 的兼容映射自动填），所以导出格式不变。

**为什么不合并成一列**：`raw_frames` 有 append-only 触发器，删列或回填都要在迁移里重建整张表，正是 §4.3 迁移纪律里风险最高的一类操作（2026-08-22 的 V2 回归事故就是这一类，见 `docs/V2-regression-postmortem.md`）；而旧帧的 `ec_raw` 是直读 EC，回填进 `kappa_25_us_cm` 会把原始读数混进计算结果。冗余的代价约为每帧 16 字节（10 Hz 连续一小时约 0.6 MB），不值得冒这个险，所以**有意保留三列**（2026-10-01 决定）。v2（`v2/`）从设计上避免了这个问题：帧表只存原始 U/I/T，κ25 查询时现算。

**calibration_records**：`id`、`experiment_id`、`calibration_id`、`sensor_path_id`、`mode`（`cell_constant` / `none`）、`standard`、`lot`、`coeff_value`（电池常数）、`coeff_json`（完整系数快照字符串：Kcell、α、温补模型、激励参数、设备标识等）、`created_at_utc`。

**fit_results**（v6+）：`id`、`experiment_id`、`sample_id`、`x_axis`、`model`、`label`、`params_json`、`r2`、`rmse`、`mae`、`aicc`、`loocv_rmse`、`n`、`x_min`、`x_max`、`extrapolation_forbidden`（0/1，默认 1）、`residual_max_abs`、`param_ci_json`、`derived_path`、`created_at_utc`。

### 4.3 迁移版本史

| 版本 | 内容 |

| 1 | V1 基线：experiments / samples / raw_frames（ec_raw 曾 NOT NULL）/ calibration_records + append-only 触发器 |
| 2 | raw_frames 加 I–V 计算链列（voltage/current/conductance/kappa_t/kappa_25） |
| 3 | samples 加判稳 QC 列 |
| 4 | raw_frames.ec_raw 解除 NOT NULL（CV 负电压合法）——同事务重建表并校验行数 |
| 5 | raw_frames 加协议溯源与激励/校准元数据列 |
| 6 | 新增 fit_results 表 |

### 4.4 停止时自动判稳（QC，REQ-D-003）

`stop` 在帧队列 flush 成功后，对**已落库**的最新 ≤500 帧执行一次判稳（`stability.qc_from_frames`），写入 `samples`（落库已降级时跳过；reset / 进程关闭的 abort 不判稳）：

- 数值窗口：只取可计算 κ25 的帧（剔除 κ25 为空或带 `COMPUTE_INVALID` 的行），取尾部 `window = 30` 点，统计 mean / median / std / CV / 线性斜率。
- 故障覆盖范围：硬异常标志与无效帧占比看的是数值窗口**覆盖的全部原始帧**（从窗口首个有效帧到最新一帧，含其间和末尾的 `COMPUTE_INVALID` 帧）——电压越界、电极脱开等故障最常见的形态就是计算链拒绝，其上的硬标志不能随数值一起被过滤掉。
- 不写 QC：原始帧少于 3 条，或既无 κ25 也无 `COMPUTE_INVALID`（旧 V1 帧）。
- 阈值（缺省，待台架标定）：`min_samples=10`、`cv_warn=0.01`、`cv_fail=0.05`、`slope_warn=0.5`、`slope_fail=2.0`（μS/cm/点，按 10 Hz 基线；实际采样率按窗口 Δt 中位数换算斜率阈值）、`invalid_fail=0.2`。
- 判定顺序：覆盖范围内有硬标志 → FAIL(`hard_quality_flag`)；有效帧 <3 或无效帧占比 ≥20% → FAIL(`invalid_frames`)；样本不足 → WARN(`insufficient_samples`)；|slope|>fail → FAIL(`drift`)；CV>fail → FAIL(`high_variation`)；|slope|>warn → WARN(`borderline_drift`)；CV>warn → WARN(`borderline_variation`)；否则 PASS(`stable`)，`representative_value` = 窗口均值。数值稳定但夹有任何无效帧时，PASS 降为 WARN(`some_invalid_frames`)，不给代表值。
- 代表值与窗口统计每次判稳整组覆写（续跑后再停止判 FAIL 时不会残留上次 PASS 的代表值）。
- 前端从 `GET /api/experiments/{id}` 的 `samples[]` 读取 `qc_status / qc_reason / representative_value` 展示 PASS/WARN/FAIL 与代表值；跨实验标定（§3.7）也按它准入。

## 5. I–V 计算链与单位约定

唯一实现：`backend/app/measurement.py::compute_chain()`（纯函数；驱动与接入方**不得**自带实现）。

```text
G(T)  = I / U                        [S]
κ(T)  = Kcell × G(T) × 1e6           [μS/cm]   （1 S/cm = 1e6 μS/cm）
κ25   = κ(T) / (1 + α × (T − 25))    [μS/cm]
```

输入校验（任一不满足 → `ValueError` → 帧标 `COMPUTE_INVALID`，Raw 照常落库）：

- `U > 0`（0/负电压无法定义电导；CV 循环伏安负电位帧即由此拒绝）
- `Kcell > 0`
- 温补分母 `|1 + α(T−25)| ≥ 1e-12`
- 所有输入必须有限（非 NaN/±inf）；计算结果也必须有限（如 U→0⁺ 使 I/U 溢出为 inf 时同样拒绝）

参数来源（`acquisition.measurement_params()`）：直接读当前驱动 config（`DriverConfig` 字段，见 §7.1）的 `cell_constant_per_cm`、`alpha_per_c`、`excitation_frequency_hz / excitation_amplitude_v`、`device_id / firmware_version / range_id / compensation_model`；没有 config 的驱动用 `DriverConfig` 缺省值。

校准声明 `calibration_claimed` 决定帧是否追加 `UNCALIBRATED`：

- 驱动显式声明 `true`（Mock）→ 已校准；显式 `false`（Simulator、CSV）→ 未校准，即使有校准编号也不覆盖；
- 未声明（`None`，`DriverConfig` 缺省）→ 存在非 `UNCALIBRATED` 的 calibration_id（`EC_CALIBRATION_ID` 或驱动声明）即视为已校准，否则未校准。

## 6. quality_flags 质量标志字典

`|` 分隔字符串，逐帧下发并落库。**实际产生**（代码路径核实）：

| 标志 | 产生方 | 含义 |
|---|---|---|
| `SIMULATED` | Mock / Simulator 全部读数 | 模拟数据源（非真实硬件） |
| `STABLE` / `REALISTIC` / `FAULT` | Simulator | 当前仿真模式（追加在 SIMULATED 后） |
| `DROPOUT` | Mock(dropout 场景) / Simulator | 丢点帧（不完整读数，不广播不落库） |
| `DISCONNECTED` | Simulator(fault_kind=disconnected) | 设备断连模拟 |
| `OUT_OF_RANGE` | Mock / Simulator | 超量程（κ<0、pH 越界、温度异常、ADC 饱和等伴随出现） |
| `TEMP_ABNORMAL` | Simulator(fault_kind=temp_abnormal) | 温度异常（T=95 °C 注入） |
| `VOLTAGE_OOR` | Simulator(fault_kind=voltage_oor) | 电压越量程（U=−0.4 V 注入，必触发 COMPUTE_INVALID） |
| `CURRENT_ZERO` | Simulator(fault_kind=current_zero) | 电流归零（判稳硬异常） |
| `ADC_SAT` | Simulator(fault_kind=adc_sat) | ADC 饱和（I=0.05 A 注入） |
| `UNSTABLE` | Simulator(fault_kind=unstable) | 不稳定注入（噪声 ×4） |
| `CSV` / `PLAYBACK` | CsvPlaybackDriver | CSV 回放读数 |
| `EOF` / `EMPTY` | CsvPlaybackDriver | 回放到末尾 / 无数据（不完整读数，静默跳过） |
| `UNCALIBRATED` | 组帧层 | 驱动未声明校准（如 CSV 回放），追加到帧标志 |
| `COMPUTE_INVALID` | 组帧层 | 计算链拒绝该帧；Derived 字段与 `ec` 为 null |
| `PERSIST_DROPPED` | 组帧层 | 落库降级拒收；该帧只到实时流、不入库 |

**预留约定值**（判稳/文档保留，当前驱动不产生）：`SATURATED`、`OPEN_CIRCUIT`、`SHORT_CIRCUIT`、`UNDER_RANGE`、`CALIBRATION_EXPIRED`、`WAVEFORM_UNSTABLE`、`TEMP_INVALID`。

**判稳硬异常列表**（窗口内出现任一 → QC FAIL）：`SATURATED`、`OPEN_CIRCUIT`、`SHORT_CIRCUIT`、`UNDER_RANGE`、`OUT_OF_RANGE`、`CURRENT_ZERO`。

## 7. 数据源驱动与运行配置

### 7.1 驱动选择 `EC_DRIVER`

| 值 | 驱动 | 特性 | 关键 config 缺省 |
|---|---|---|---|
| `mock`（缺省） | `MockDevice` | 确定性 κ25 仿真（基值 1413 + 漂移 + 噪声），由目标 κ25 反推 U/I；场景 `stable/noisy/drift/dropout` | `device_id=MOCK-IV-01`、`range_id=WIDE`、激励 `excitation_amplitude_v=1.0` V @1000 Hz、`calibration_id=MOCK-KCELL-1.0`（`calibration_claimed=true`） |
| `simulator` | `SimulatorDriver` | 虚拟两电极池 + 电压扫描（0.2→1.0 V，settle 0.5 s + sweep 8 s）；模式 `stable/realistic/fault`，8 种故障注入 | `device_id=SIM-IV-01`、`range_id=SIM`、`calibration_id=SIM-KCELL-1.0`（`calibration_claimed=false` → 帧带 `UNCALIBRATED`） |
| `csv` | `CsvPlaybackDriver` | 回放 4 列 CSV（`time_s, voltage_v, current, temperature_c`）；CV 负电压帧如实回放 → COMPUTE_INVALID；支持变速/循环 | `device_id=CSV-PLAYBACK-01`、`range_id=CSV`、激励频率 0（直流）、`calibration_id=UNCALIBRATED`（`calibration_claimed=false`） |

## 8. 前端接入要点

- **唯一配置入口** `frontend/src/config/config.ts`：`VITE_WS_URL`、`VITE_API_BASE`（浏览器内置模拟模式 `VITE_DATA_SOURCE=browser` 已于 2026-10-01 删除，前端只连后端）。缺省规则：dev 连 `http://<hostname>:8000`；build 产物同源（`window.location.origin`）。
- **REST 客户端** `services/apiClient.ts`：`control(start|stop|reset)`、`getCurrentExperiment`、`listExperiments`、`getExperiment(id)`、`getFrames(id, limit=3000, mode='head')`、`fitPoints(points, models, x_axis, experimentId?)`、`fitCalibration(experimentIds, models)`、`exportUrl(id, 'csv'|'json')` + `downloadExport` blob 下载（页面上统一用 `components/ExportLink`）。JSON 接口共用 `request()`：非 2xx 抛出「<动作>失败：HTTP <状态码>」；`fitCalibration` 例外，会把后端 400 的 `detail`（哪个实验不合格）带进错误信息。
- **WS 客户端** `services/websocketClient.ts`：自动重连（指数退避 ≤5 s）、3 s 无数据看门狗（仅 running）、非法帧丢弃并提示；协议解析唯一来源 `types/protocol.ts::parseServerMessage`（新增字段全部可选，向后兼容旧后端）。
- **实时缓冲**（`lib/realtimeBuffer.ts`）：最大 20 000 点（超限丢最旧），按帧的 `experiment_id` / 状态帧 / 重连后的 `/api/experiment/current` 对齐所属实验，换实验先清空；续跑时用 `getFrames(id, 20000, 'tail')` 水合。
- **曲线参数**：200 ms 刷新节流、3 s 超时判定；图表显示按等间隔抽样（保留首末点，`lib/downsample.ts`）限点，拟合输入超过 20 000 点时同样抽样。
- **协议类型权威定义**：`frontend/src/types/protocol.ts`（`ExperimentFrame` / `StatusFrame` / `ControlResponse` / `ExperimentSummary` / `SampleSummary` / `RawFrame` / `FitResultItem` 等，与本文档表格一致）。
