# 已知问题与后续建议（交付物 #6）

> 最后核对：2026-08-23，基于严格 V2 电极 I–V 软件链路。这里列的是当前限制，
> 不再保留已经修复的 V1 协议、DROPOUT 丢帧或单曲线描述。

## 当前未解决的问题

1. **P01（200 ms 显示延迟）没有端到端精确计时断言**

   现有 E2E 验证数据会持续到达和刷新，但未把服务端发送时间、浏览器接收时间与像素更新
   放在同一时钟下测量。当前实现为“帧到达即入缓冲、图表每 200 ms 更新”；正式验收仍需在
   目标树莓派、网络和浏览器环境中记录延迟分布。

2. **P03（30 分钟长跑）默认跳过**

   用例位于 `tests/e2e/tests/stability.spec.ts`，通过环境变量显式启用：

   ```powershell
   $env:STABILITY_MINUTES='2'; npx playwright test -g "P03"    # 快速冒烟
   $env:STABILITY_MINUTES='30'; npx playwright test -g "P03"   # 完整验收
   $env:STABILITY_MINUTES=$null                                 # 恢复默认跳过
   ```

3. **物理测量链尚未完成台架验证**

   Mock 与浏览器模拟源已经输出严格 V2 U/I/T，并统一计算 G、κ(T)、κ25；尚未接入真实激励源、
   电压/电流 AFE、ADC 和温度通道，也没有可声明的精度、量程、重复性或温补误差。

4. **结果区统计只在 stopped/idle 显示**

   运行中不展示最终统计，避免把尚未判稳的数据误作结果。若增加实时滚动统计，必须与最终代表值、
   判稳和 QC 状态明确区分。

5. **质量标志在 SQLite/CSV 中仍为兼容文本**

   `raw_frames.quality_flags` 使用 `|` 分隔以兼容已有数据库和 CSV。历史 JSON API 已额外返回
   `quality_flags_list: string[]`，前端优先使用结构化字段；后续若升版数据库格式，应通过迁移完成，
   不得改写既有 raw_frames。

## 环境相关问题（Windows + Edge channel）

1. **Playwright worker 收尾时可能等待较久**

   使用 `E2E_BROWSER=msedge` 时曾观察到用例执行结束后浏览器进程退出缓慢。优先使用 Playwright
   自带 Chromium；必须使用系统 Edge 时，应在测试结束后确认没有残留的测试浏览器进程。

2. **Edge 对 `<a download>` 的事件行为不同**

   Edge 可能把下载交给内置下载中心，导致 `page.waitForEvent('download')` 不稳定。当前 E2E 直接通过
   `page.request.get` 校验 CSV 内容，后端导出接口与用户下载按钮不受影响。

## 限制说明

- **单传感路径展示**：实时图已分层显示 κ(T)、κ25、U、I，并有独立温度图；尚未实现多个
  `sensor_path_id` 的同图叠加和比较。
- **无鉴权**：当前 REST/WS 面向受控局域网演示，没有用户认证和权限模型；调试接口默认关闭，
  只有 `EC_ENABLE_DEBUG_ENDPOINTS=1` 时开放。
- **树莓派部署未实机闭环**：`scripts/deploy/setup.sh` 仍需在目标 Raspberry Pi OS、权限和显示环境中验收。
- **报表格式有限**：当前提供 CSV/JSON；PDF/原生 Excel 报表、签名和审计封装尚未实现。
- **判稳与 QC 未实现**：`samples.k25_*` 统计、代表值、PASS/WARN/FAIL 和失败原因仍属后续阶段。
