# 已知问题与后续建议（交付物 #6）

> 当前仍未解决的问题统一登记在这里（2026-10-01 起为唯一登记处）。
> 历轮审查的逐条记录、已修项与修复提交见 `docs/审查与修复记录.md`；括号里的 B/N/P 编号可在那里查到原始描述。

## 当前未解决的问题

1. **P01（200ms 延迟）未做精确自动化断言**
   现有 E2E 只断言"数据能及时到达"（轮询超时 8s）。精确的 200ms 延迟测量依赖真实网络环境，已在设计中保证（WebSocket 帧到达即写入缓冲，曲线 200ms 节流刷新），验收现场可手动观察。

2. **P03（30 分钟长跑）为可选用例，不随默认套件跑**
   时间较长，放在 `tests/e2e/tests/stability.spec.ts`，通过环境变量控制时长：
   ```bash
   STABILITY_MINUTES=2 npx playwright test -g "P03"    # 快速冒烟
   STABILITY_MINUTES=30 npx playwright test -g "P03"   # 完整 30 分钟验收
   ```
   实测：30 分钟运行期内每 15s 探活（点数增长/连接/状态）全部通过，未出现崩溃或停更；
   但运行结束后 Playwright worker 关闭时被强杀（见下方环境问题 E1），未输出最终 PASS 标记。

3. **结果区统计只在 stopped/idle 显示**
   目前实验结果区在实验运行时不显示（避免抢占视线）。若需要"实时滚动统计"，可后续在 running 状态也渲染。

4. **simulator `UNSTABLE` 故障判 FAIL 依赖统计阈值，未做台架标定**
   `UNSTABLE` 只放大 4× 噪声并打标志，判稳靠 cv/slope 阈值；窗口内 κ25 均值较大时 cv 被稀释，可能出现"已注入不稳定却 PASS"。属"软故障靠统计判据"的既定设计，待 QC 阈值台架标定（Phase 8）后复核（09-11 复审 P2-10 登记）。

5. **负电流不打质量标志（N5）**
   U > 0、I < 0 时计算链照常产出负的 G / κ(T) / κ25，帧上没有任何质量标志（负电压会被计算链拒绝并标 `COMPUTE_INVALID`，负电流不会）。真实硬件接入时应在驱动或计算链加极性检查。

6. **落库降级不自愈**
   一次批量写入失败后，持久化进入进程级降级闩锁、拒收后续帧（防止内存无限增长）；数据库恢复后也要重启后端才能恢复落库。前端会持续提示"落库失败，请重启后端"。

7. **图表细节**
   - 实时曲线（EC-t、V/I 波形）的 Y 轴在同一实验内只扩不缩，早段尖峰会把轴一直撑大，稳态信号被压扁（B3）。
   - I–V 图电流单位在 1 mA 处切换没有迟滞，读数在阈值附近波动时单位会来回跳（B5 残留）。
   - EC-t 诊断图的全量重建计数包含 κ25 为空的点，会略早触发重建（B6，仅影响性能）。
   - 静态曲线图 Y 轴名固定为 `EC (μS/cm)`，叠加非 EC 曲线时标注不准（B7）。
   - V/I 波形图每 200ms 整表 `setOption`（≤4000 抽样点 × 2 条），在树莓派上属已接受的性能开销。

8. **导出在内存中整包生成**
   CSV 全文在内存拼好再返回；JSON 导出上限 100 万帧（超出置 `truncated: true`）。超长实验的流式导出留待有真实需要时设计。

9. **无鉴权，控制接口可被跨站触发**
   模拟源无认证，CORS 放行局域网段（仅用于开发与演示）。`stop`/`reset` 与不带请求体的 `start` 属浏览器"简单请求"，CORS 拦不住，任意网页都能借访问者的浏览器发控制请求（09-30 审查登记）。上生产前需加鉴权，并校验 `Origin` 或加 CSRF token。

10. **几处性能开销待树莓派实测再定**（10-01 复审登记，有意未改）
   - 拟合放在工作线程里跑，但纯 Python 计算持有 GIL，会和事件循环争用：2 万点本机约 1.6s，树莓派估计 3–4s，期间采集节拍和 WS 推送可能抖动。
   - 实验详情接口串行发起 5 次线程池查询、各开一个数据库连接；实验列表对每个实验用子查询 `COUNT` 帧数。数据量小时感觉不到，等真实数据量下测过再决定是否合并查询或缓存帧数。

## 环境相关问题（Windows + Edge channel 实测）

E1. **Playwright worker 关闭时偶发 300s 强杀等待**
   本机使用 `E2E_BROWSER=msedge`（Edge channel）运行完整套件时，**所有用例通过**
   （当前 E2E 共 30 个用例，其中 P03 长跑用例默认跳过），
   但套件收尾时 worker 进程 5 分钟内未退出被强制结束，日志出现
   `Error: worker-0 process did not exit within 300000ms after stop`。
   这是 Windows 下 Edge/Chrome channel 的进程清理问题，**不影响用例结果**。
   规避：在可联网机器上执行 `npx playwright install chromium` 后去掉 `E2E_BROWSER` 运行，或运行后手动结束残留 msedge。

E2. **Edge channel 下 `<a download>` 不触发 Playwright download 事件**
   CSV 导出按钮是 `<a download>` 链接；Edge channel 会把它交给浏览器自带下载中心处理
   （页面导航到 `edge://downloads-hub/`），`page.waitForEvent('download')` 会一直挂起。
   E2E 已改为**直接用 HTTP 请求断言 CSV 内容**（`page.request.get`），后端导出逻辑不变，
   功能等价且跨浏览器稳定。

E3. **E2E 前要清掉陈旧的 Vite 进程**
   `playwright.config.ts` 本地 `reuseExistingServer: true`：若 :5173 上残留状态损坏的旧 Vite dev server，会被直接复用，全部用例白屏失败。跑 E2E 前先确认 :5173、:8000 没有旧进程。

## 限制说明

- **真实后端未就绪**：当前所有验证基于模拟源（Mock / Simulator / CSV 回放）。真实采集驱动接入时按 `docs/接入数据格式.md` §4 的驱动契约实现、按 `docs/数据接口文档.md` 对齐协议；协议如有差异，前端只改 `services/` 或 `types/protocol.ts`，页面层不受影响。
- **树莓派部署**：`scripts/deploy/setup.sh` 按 Raspberry Pi OS 桌面版编写。Pi 5 8GB 可在设备上构建；生产由 FastAPI `:8000` 托管 `dist`。未在每台实机上跑通验证，路径/权限需按实际环境微调。
- **报表导出为 CSV/JSON**：任务书要求的 PDF/Excel 报表尚未实现，当前 CSV 可直接用 Excel 打开；PDF 报表可后续基于已存数据生成。
- **移动端适配缺失**：按桌面 1080p/笔记本设计，平板/手机需补充断点布局。
